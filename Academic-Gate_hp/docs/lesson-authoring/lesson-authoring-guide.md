## 0. この指示書の使い方

- あなた（記事を書く側）は、サイトのリポジトリを見られない。必要なことはこの指示書とひな形にすべて書いてある。ここに無いことは、推測で決めずに質問する
- **記事は、ひな形 `lesson-template.html` を複製して書く。** 一から HTML を組まない。ひな形の CSS・スクリプト・外側の構造は、公開中の記事（サイバーセキュリティ基礎 0-1）と同じもの
- ひな形には、どの分野でも使う「共通の部品」と、分野によって使う「オプションの部品」（§7）の見本が入っている。オプションの部品は `<!-- ▼ オプション：… -->` から `<!-- ▲ オプション：… ここまで -->` までで囲んである。**使わないオプションは、その印の行ごと消す**（`<head>` の中の CSS とスクリプトのオプションも同じ）
- 完成した HTML は、サイトの担当が組み込む。組み込みで使われるのは次の部分だけ：
  - `<title>`、`<meta name="description">`、`<body>` の `data-node`
  - 目次レールの `.brand` と `.toc` の中身
  - `<main>` の中身（`dg-sprite`、`.lesson-hero`、`<section>`（§01〜）、`.foot`）
  - `<head>` の「B'」の CSS と、残したオプションの読み込み（数式など）
  - それ以外（`<head>` の A・B・C の CSS、単体表示用のヘッダー・フッター、末尾のスクリプト）は、サイトのものに置き換わる。**そこを書き換えても、サイトには反映されない**
- ひな形に無い形を発明しない。どうしても新しい部品が要るときは「B'」の最後の `<style>` に CSS を足し、渡すときに報告する（§1）

## 1. 作るものと渡し方

- 1つの記事（節）＝ 1つの HTML ファイル：`<接頭辞>_X-Y.html`（例：`cyber_0-2.html`、`polisci_1-1.html`。接頭辞は §3・§4）
- 保存先：**ダウンロードフォルダ**（ダウンロードできるファイルとして渡す）
- 画像は HTML の中に data URI で埋め込む（§9）。英語の札を描いたスクリーンショットがあれば、別のファイルとしても渡す：`<接頭辞>_X-Y_sNN_en.jpg`
- 英語版の HTML を頼まれたとき（日本語版が確定した後。§2）は `<接頭辞>_X-Y_en.html` として渡す
- **この記事が階層のどこに入るか**を、HTML の冒頭の「階層」の注釈に書く（学問・シリーズ・部・章・節番号・節の題・目次に載せる説明の一行。§3）
- **新しいシリーズの最初の記事**を渡すときは、シリーズの情報 `<接頭辞>_series.md` も一緒に渡す（部・章・節の構成と、各節の説明の一行。§4）
- 渡すときに、次を短く報告する
  1. 記事の種類（共通／日本語限定／英語限定）と、階層の注釈の中身（学問・シリーズ・部・章・節・題・説明の一行）
  2. 残したオプションの部品（§7）と、「B'」に足した部品があればその名前と理由
  3. 未公開の節を本文で参照した箇所（リンクを付けていないこと）
  4. 埋め込んだ画像の一覧（`data-file`・縦横の画素数）と、英語の札の画像の有無
  5. 用語集（§13）に無い語を英訳したときは、その語と訳（英語版のとき）
  6. §14 のチェックリストの結果

## 2. 記事の種類と、日本語・英語の順番

- 記事の種類は3つ。**ファイルの冒頭（`<!DOCTYPE html>` のすぐ下）のコメント**で示す。ひな形の1行目のコメントを、どれか1つに書き換える

```html
<!DOCTYPE html>
<!-- 記事の種類：共通（日本語・英語） -->
```

| 種類 | コメントの書き方 | 意味 |
|---|---|---|
| 共通 | `記事の種類：共通（日本語・英語）` | 日本語版と英語版の両方を作る。ふつうはこれ |
| 日本語限定 | `記事の種類：日本語限定` | 日本語版だけ。翻訳しない（日本の制度の細部など、英語の読者に向かないもの） |
| 英語限定 | `記事の種類：英語限定` | 英語版だけ。翻訳しない |

- **共通の記事は、日本語版を先に確定させ、英語版はその後に作る。** 日本語版が確定する前に英語版を作らない
  - 確定した後に日本語版を直したときは、英語版も同じように直す（英語版だけが古いまま、を作らない）
- スクリーンショットに札（赤枠の番号と説明の文字）を描くときは、日本語版の画像と、英語の札を描いた画像の2種類を作る（§9）

## 3. サイトの階層・ファイル名・番号・リンク

### サイトの階層

教材の記事は、サイトの次の階層のいちばん下に入る。上の3段（勉強の軌跡・学問のページ・シリーズの目次）はサイトの担当が作り、記事を書く側は作らない。

```
勉強の軌跡（study.html）
└─ 学問のページ（study_<学問>.html。例：study_informatics.html 情報科学）……34の学問のうち1つ（付録C）
   └─ シリーズの目次（<接頭辞>.html。例：cyber.html サイバーセキュリティ基礎）
      └─ 部（例：部 I 基礎 — ネットワークとセキュリティの土台）……部の無いシリーズもある（例：物理数学）
         └─ 章（例：0章 準備編：コンピューターの基礎）
            └─ 節の記事（<接頭辞>_X-Y.html。例：cyber_0-1.html）← あなたが書くもの
```

| 段 | ページ | 例 | 誰が作るか |
|---|---|---|---|
| 勉強の軌跡 | `study.html` | — | サイト |
| 学問 | `study_<学問>.html` | `study_informatics.html`（情報科学）・`study_physics.html`（物理学） | サイト（学問のページが無ければ、新しいシリーズのときに作る） |
| シリーズ（目次） | `<接頭辞>.html` | `cyber.html`・`phys-math.html` | サイト（`<接頭辞>_series.md` から作る） |
| 部・章 | 目次ページの中の見出し（ページは無い） | 部 I／0章 | サイト（目次ページの中） |
| 節 | `<接頭辞>_X-Y.html` | `cyber_0-1.html` | **記事を書く側** |

- 目次ページでは、1つの節が1行（番号・題・説明の一行）で並ぶ。PC では右にプレビューが出て、題・説明の全文・部と章・その記事の §の見出し（目次レールの項目。§5）・「読む →」を見せる（付録D）
- 右のサイトの階層パネル、レールの上の「← シリーズ名」、記事の末尾の前後の節へのリンクは、サイトの階層の表から自動で作られる

### この記事の位置を渡す（階層の注釈）

記事の HTML の冒頭（「記事の種類」の注釈のすぐ下）に、この記事が階層のどこに入るかを書く。ひな形にある形をそのまま使う。

```html
<!-- 階層（この記事がサイトのどこに入るか。指示書 §3。eyebrow・title・h1・.brand・data-node と食い違わないこと）
     学問：情報科学（cs）
     シリーズ：サイバーセキュリティ基礎（cyber）
     部：部 I 基礎 — ネットワークとセキュリティの土台
     章：0章 準備編：コンピューターの基礎
     節：0-1
     題：ビット・バイトと2進数・16進数
     説明：MAC アドレスやポート番号を、バイトと16進数で読む
     ↑ 見本の値。この記事の値に書き換える。部の無いシリーズは「部：なし」 -->
```

- 学問は付録Cの名前と key、シリーズは名前と接頭辞
- **既存のシリーズ**の記事は、この注釈だけでよい。部・章・節番号・題は付録Bの目次と同じにする。説明の一行を目次から変えたいときは、新しい一行を書き、報告で「説明の一行を変えたい」と書く
- **新しいシリーズ**の記事は、この注釈に加えて `<接頭辞>_series.md`（§4）を渡す。注釈の中身は `<接頭辞>_series.md` の目次と同じにする

### 目次に載せる題と説明の一行の長さ

目次ページの PC 表示（幅 769px 以上）では、1つの節が「番号・題・説明」の1行に並び、入りきらない分は「…」で省略される（全文はプレビューに出る）。省略されずに読めるよう、次の長さを目安にする。日本語は **1280px 以上の画面で1行に収まる**目安、英語は 1024px で測った目安。

| | 題 | 説明の一行 | 題＋説明 |
|---|---|---|---|
| 日本語（全角1字で数える。半角の英数字は0.5字） | 15字前後、最大20字 | 15〜17字前後 | **32字以内**（1280px 以上で1行に収まる目安） |
| 英語（文字数。空白を含む） | 30字前後、最大45字 | 35字前後 | **65字以内** |

- 日本語は、1024px 前後の画面では、目安の中でも説明の終わりが省略されることがある（句読点や英字を含む実際の文は、測るのに使った文より幅を取るため。1024px で省略されないのは、合わせて28〜29字程度）。プレビューで全文が見えるので、それでよい
- 目安は、PC で1行に収めるための基準。大事な語が落ちるくらいなら、少し超えてもよい（省略されても、プレビューで全文が見えるため）
- 題だけで、日本語21字・英語45字を超えると、説明が見えなくなる
- 説明の一行は、その節で何ができるようになるかを、名詞止めか短い文で（句点「。」は付けない）。題を言い換えるだけにしない
- スマホ（768px 以下）では2段（1段目 番号と題、2段目 説明は2行まで）。上の目安の長さなら、どちらも省略されない
- 題は、記事の h1・`.brand`・title・eyebrow の題と同じ文字列にする

### 階層との食い違いをなくす

記事の中の次の部分は、階層の注釈（と目次）と同じ値にする。サイトのパンくず（右の階層パネル・レールの「← シリーズ名」）と前後の節へのリンクは、サイトの階層の表から作られるので、記事の値がずれると、同じページの中で名前や番号が食い違って見える。

| 記事の中の場所 | 階層の注釈の値 |
|---|---|
| ファイル名・`data-node` | `<接頭辞>_<節>`（例：`cyber_0-1`） |
| eyebrow | `シリーズ名 ／ 章 ／ SECTION 節`（部は eyebrow に入れない） |
| `<title>` | `節 題｜シリーズ名 X章 \| Academic Gates` |
| h1・`.brand` | `節＋全角スペース＋題`。`.brand` の `<small>` は `シリーズ名 ／ 章` |
| description の末尾 | `シリーズ名 X章／節。` |
| `.transfer`「次へ」「前へ」 | 行き先の節の番号と題を、目次と同じ文字列で |

- 前後の節へのボタン・パンくずを記事に書かない（サイトが作る。§11）
- 章や題を変えたいときは、記事だけを変えず、報告で知らせる（目次と階層の表もサイトの側で一緒に変える）

### ファイル名と番号

- ファイル名は `<接頭辞>_<章>-<節>.html`。接頭辞はシリーズごとに1つ（いまあるもの：`cyber`＝サイバーセキュリティ基礎、`phys-math`＝物理数学）。新しいシリーズの接頭辞の決め方は §4
- `X-Y` は「章-節」。章と節の番号と題は、そのシリーズの目次（いまあるシリーズは付録B、新しいシリーズは `<接頭辞>_series.md`）にあるものを使う。目次に無い節を書くよう頼まれたら確認する
- `<body>` の `data-node` はファイル名から `.html` を除いたもの：`data-node="cyber_0-2"`

### title と description

| | 書き方 | 例 |
|---|---|---|
| `<title>` | `X-Y 節の題｜シリーズ名 X章 \| Academic Gates` | `0-1 ビット・バイトと2進数・16進数｜サイバーセキュリティ基礎 0章 \| Academic Gates` |
| description | 内容を2〜3文。末尾に `シリーズ名 X章／X-Y。` | `…読み直す。サイバーセキュリティ基礎 0章（準備編）／0-1。` |

（`|` の前後は半角スペース、`｜` は全角）

### 小節の番号

- 本文は小節に分け、`§01`・`§02`… と2桁で番号を付ける（`<div class="sec-head"><span class="idx">§01</span><h2>…</h2></div>`）
- `<section>` の id は `s1`・`s2`…（ひな形のとおり）。目次レールの `href="#s1"` と一致させる
- 本文の中で別の小節を指すときは「§03」、別の節を指すときは「1-4 §05」のように書く

### リンク

- 行き先は、ファイル名だけの相対パスで書く：`<a href="cyber_1-1.html">1-1「パケットとIP」</a>`（`../` も `https://` も付けない）。外部のページ（出典など）は `https://` から書く
- **公開済みの節にだけリンクを付ける。** 公開状況は付録B（新しいシリーズは、依頼のときに知らせる）。まだ無い節は、題や番号を文字で書くだけにする（「次の 0-2 では…」）。迷ったら付けない
- シリーズの目次のページ（`<接頭辞>.html`。例：`cyber.html`）へのリンクは付けてよい（新しいシリーズでは、目次のページができるまで付けない）
- 前後の節へのボタン（「前の節」「次の節」「目次へ」）と、レールの上の「← シリーズ名」は、**サイトが自動で付ける。記事には書かない**
- 記事の中で前後の節を案内するときは、最後の小節に `.transfer` の囲みで書く（§6）

## 4. 新しい分野・シリーズを始めるとき

新しいシリーズ（例：政治学の入門シリーズ）の最初の記事を書くときは、記事と一緒に、次を決めて **`<接頭辞>_series.md`** として渡す。サイトの担当は、これをもとに目次のページ・学問のページ・サイトの階層を作る（記事を書く側は、それらのページを作らない）。

### 決めること

| 項目 | 決め方 |
|---|---|
| シリーズ名 | 日本語と英語。短く、内容が分かる名詞句（例：サイバーセキュリティ基礎／Cybersecurity Fundamentals）。英語は §13 の用語集の書き方に合わせる |
| 接頭辞（ファイル名の頭） | 英小文字・数字・ハイフンだけ、12文字まで。学問かシリーズの英語名の略から作る（例：政治学 → `polisci`、物理数学 → `phys-math`）。いまある接頭辞（`cyber` `phys-math` `memoryverse`）とサイトのページ名（`index` `study` `self-intro` `videos` `blog` `sns` `study_…` など）と重ならないこと。**URL になるので、一度決めたら変えない**。同じ学問に別のシリーズが増えそうなら、内容の語を足す（例：`polisci-jp`） |
| 属する学問 | 付録Cの34分野から1つ（key で書く。例：`politics`）。2つにまたがるときも1つに決め、もう1つは説明に書く |
| 記事の種類 | シリーズの記事の多くが共通か日本語限定か（§2） |
| 目次 | 部（必要なら）→ 章 → 節。各節に番号・題・説明の一行（長さの目安は §3）。章は 1 から（準備の章を前に置くなら 0 から）。各章の節は 1 から。章に説明を付けるなら1〜2文 |
| 学問の説明（学問のページがまだ無いとき） | 勉強の軌跡に出す、学問の説明の1文（日本語・英語） |
| シリーズの説明 | 目次のページの冒頭に出す、副題の1行とリード文（日本語・英語） |

- 部・章・節の数を、目次やシリーズの説明に書かない（§11。量で圧倒しない）
- サイトの担当は、これをもとに目次ページを付録Dの形で作る。各節の行の「題」「説明の一行」がそのまま目次に出る

### `<接頭辞>_series.md` の形

```markdown
# シリーズの情報：<シリーズ名>

- シリーズ名：政治学入門 / Introduction to Political Science
- 接頭辞：polisci
- 学問：politics（政治学 Political Science）
- 記事の種類：共通（日本語・英語）
- 副題：…（日本語） / …（英語）
- リード文：…（日本語） / …（英語）
- 学問の説明（学問のページが無いとき）：…（日本語） / …（英語）

## 目次

### 部 I　部の題（日本語） / Part I Title (English)

#### 1章 章の題 / Ch. 1 Chapter title
章の説明（任意。1〜2文。日本語） / Chapter lead (optional, English)
- 1-1 節の題 / Section title — 説明の一行（日本語） / One-line description (English)
- 1-2 …

#### 2章 …
```

（部を使わないシリーズは、`### 部` の行を書かずに `#### 章` から並べる）

## 5. ページの構成

ひな形の構成をそのまま使う。上から順に：

```
<body data-page="study" class="is-article" data-node="<接頭辞>_X-Y">
  単体表示用のヘッダー（「講座一覧」ボタン1つ）……組み込むと消える
  <button class="menu-btn btn" id="menuBtn">この記事の目次 ≡</button>   ……スマホでレールを開くボタン
  <div class="scrim" id="scrim"></div>
  <div class="wrap">
    <nav class="rail" id="rail">           ……左の目次レール
      .brand（記事の題＋小さい行）
      .progress-wrap（読み進めたバー）
      <ul class="toc" id="toc">（部分けの見出し li.part と、小節へのリンク）
    </nav>
    <main class="main">
      <svg class="dg-sprite">……図の矢印とアイコン。消さない
      <div class="lesson-hero">（eyebrow・h1・sub・lead）
      <section id="s1">§01 …</section>
      …
```

#### 目次レールの項目名は、目次ページのプレビューにそのまま出る

- シリーズの目次ページのプレビュー（PC）の「この節で学ぶこと」は、**この記事の目次レール（`.rail .toc` の各リンク）を読み取って**、番号と項目名をそのまま並べたもの。部分けの見出し（`li.part`）は出ない。つまり、レールの項目名は、記事を開く前の読者が「この節で何を学ぶか」を知る一覧になる
- 項目名の書き方

  - 「導入」「その1」「演習」のような、中身の分からない名前にしない（「端末で計算して確かめる」のように、何をするかを書く）

  - 最後の項目は「まとめとチェック」
- 項目の書き方（`<li><a href="#s1"><span class="n">01</span>項目名</a></li>`）を変えない。プレビューは `.toc` の中の `a` と `.n` を読む

### 囲み（.box）

| class | 色 | 用途 | いま使っている見出し（.lab）の例 |
|---|---|---|---|
| `box target` | 緑 | その小節の要点・到達目標・定義 | この節で押さえること／定義：○○ |
| `box principle` | 桃 | 最後の確認・前提・定義 | 最終チェック／前提として使うもの |
| `box warn` | 琥珀 | 注意・よくある誤り・失敗したとき・後片付け | うまくいかないとき／後片付け／よくある誤り |
| `box teach` | 紫（見出しの前に ◎ が自動で付く） | 補足・用語の由来・「なぜ〜か」 | 2進数を書くときの約束／traceroute の仕組み |

### 本文の文字

- 強調は `<strong>`（太字＋白）。斜体は使わない
- 名前・値・記号・ファイル名は `<code>`（等幅・青）：`<code>192.168.128.3</code>`
- 補足の小さい字：`<p style="font-size:13.5px;color:var(--ink-faint)">…</p>`
- `<` `>` `&` は `&lt;` `&gt;` `&amp;` と書く
- 略語は初出で開く：`MAC アドレス（MAC：Media Access Control：媒体アクセス制御）`

### 表

```html
<div class="table-scroll"><table class="mini-table">
  <caption>表の題（あれば）</caption>

```

- 表は必ず `<div class="table-scroll">` で包む（スマホで表だけ横に送れる）

```html
    <tr><td class="edge-green">アプリケーション</td><td><code>HTTP</code></td><td>データの中身をやり取りする</td></tr>
```

### 図（SVG。.fig.dg）

```html
<figure class="fig dg">
  <svg viewBox="0 0 760 170" role="img" aria-label="図の内容を1文で">…</svg>
  <figcaption><strong>図1</strong>　図の説明。</figcaption>
```

- コードで描く図は、ページの中の SVG で描く。`class="fig dg"`、`viewBox` の幅は **760**（高さは中身に合わせる）。スマホでは図だけ横に送れ、「← 図は横にスクロールできます →」が自動で出る
- `<svg>` には `role="img"` と `aria-label`（図の内容を1文で）を付ける
- 図の番号は記事の中で通し番号：`<strong>図1</strong>`＋全角スペース
- **図のアイコンと矢印の部品（`<svg class="dg-sprite">`）は、ひな形の `<main>` の先頭にすでに入っている。** 図の側で `<symbol>` や `<marker>` をもう一度書かない（同じ id が2つになり、どちらが使われるか分からなくなる）。図からは `<use href="#i-…">` と `url(#m-…)` で参照するだけ

- 色は次の組（線・枠の色／その上の文字の色）。塗りは同じ色を `fill-opacity` で薄くする（濃さは下の「塗りと線の濃さ」の表）

```html
<h3>確認問題（§01・全3問）</h3>

<div class="drill"><p><span class="qn">問1</span>問題文。<br>(a) …　(b) …</p>
<div class="attempt" style="margin:10px 0 4px"><span class="lab">自分の答えを出してから</span>
```

- 解答（`.sol`）は最初は閉じている（CSS で隠れている。開いておく指定をしない）。「解答を見る」を押すと開き、ボタンが「閉じる」になる
- 問題の番号は**記事の中で通し番号**（問1 から始め、小節が変わっても続ける。公開中の cyber_0-1.html は 問1〜問12）。本文や解答から「（問11）」のように1つに決まる番号で指せるようにするため。公開中の物理数学の記事は小節ごとに 問1 からだが、構成を見直し中なので、新しい記事は通し番号にする
- 見出しは「計算ドリル（§02・全3問）」「応用問題（§06・全4問）」「確認問題（§01・全2問）」の形。**問題数は書く**（1つの問題セットの問題数は、§11 の「量の数字」の対象外）

- `.drill`・`.attempt`・`.sol` の閉じタグの数に注意（上の形で `</div></div></div>`）

## 7. オプションの部品（分野によって使うもの）

ひな形の §02「分野ごとの部品の見本」に、すべてのオプションの見本が並んでいる。使う部品を本文の必要な場所に移し、使わない部品は印の行ごと消す。最後に §02 の見本の小節そのものも消すか、本文の小節に書き換える。

## 8. 分野別の決まり

### 8.1 技術系（サイバーセキュリティ基礎など）

#### 演習の環境と、注意書きの入れ方

- **演習は、自分が管理する環境（自分の仮想マシンやラボ）の中だけで行う。** 記事には次の2か所で書く
  1. 手を動かす小節の最初の段落：どの環境の端末で行うか、通信をするか（するなら、どのネットワークの中だけか。外へ出るならその内容）
  2. `.foot`：演習を行った環境を書き、最後の文は必ず次の文にする
     「自分が管理していないネットワークや機器には、この講座の操作を行わないでください。」
- サイバーセキュリティ基礎の環境：Kali Linux と Parrot OS の仮想マシン。内部ネットワークは Host-Only の `192.168.128.0/24`（Kali `192.168.128.2`、Parrot `192.168.128.3`）。インターフェース名は Kali が `eth1`、Parrot が `enp0s2`。Parrot の NAT 側の出口は Mac の `192.168.64.1`

#### コマンドとコピーボタン（.cmdbox）

```html
<div class="step">
  <span class="sh"><span class="sn">COMMAND</span>このコマンドで何をするか</span>
  <div class="cmdbox" data-copy="echo $((2#1010))"><code class="cmd">echo $((2#1010))</code></div>
</div>
```

- コピーボタンはスクリプトが自動で付ける。HTML にボタンを書かない
- `data-copy` がコピーされる文字列。**画面の表示と同じ文字列にし、先頭に `$` や `#` のプロンプトを付けない**
- `"` を含むコマンドは、`data-copy` の中で `&quot;` と書く：`data-copy="python3 -c &quot;print(1)&quot;"`
- 1つの枠に1つのコマンド（`;` でつないだ1行はよい）
- `.sn` の札：`COMMAND`（ふつう）、`端末A`・`端末B`（端末を2つ使うとき）、`準備`
- 手順には `<h3>手順1：…</h3>` の見出しを付ける

#### 出力例（.out）と分解表（.anat）

```html
<div class="out"><span class="lab">出力例</span>enp0s2           UP             5e:f1:1e:25:27:db &lt;BROADCAST,MULTICAST,UP,LOWER_UP&gt;</div>

<div class="table-scroll"><table class="mini-table anat">
  <caption>コマンドの分解</caption>
  <thead><tr><th>部分</th><th>意味</th></tr></thead>
  <tbody>
    <tr><td><code>-br</code></td><td><strong>brief</strong>（簡潔）。1行にまとめて表示する。</td></tr>
  </tbody>
</table></div>
```

- 出力例はコピーの対象ではない。改行はそのまま書く。複数のコマンドの結果をまとめるときは `出力例（4つのコマンドの結果を順に）`
- 分解表の見出しは「コマンドの分解」「出力の読み方」。オプションは元の英語も書く。前の節と同じ部分は短く書き、「（1-1 §04）」のように出てきた場所を添える
- 自分の環境で変わる値（MAC アドレスなど）は、本文でそう書く

### 8.2 数学・物理系（物理数学など）

- **物理数学の記事の構成は見直し中。** 新しい記事は、汎用のひな形に数式のオプションを残して作る（公開中の物理数学の記事のヒントの部品・図の形は、見直しが終わるまで使わない）
- 原理から積み上げる記事では、`.road`（原理 P・導出 D・言えること C）を本文の中に1つずつ置き、最後の小節で「この記事の道筋（ふり返り）」の図にまとめる。最終チェックの最初の項目は「**何も見ずに**、原理 P1〜Pn を書き出し、そこから D1〜 を順に導き、C1〜 を説明できるか」
  - 問題の札：`<span class="qt re">再現：D2</span>`（緑）、`<span class="qt ap">応用：P3 → C1</span>`（橙）。解答の先頭に `<p class="qu">使う：P2・D2</p>`

#### 数式（MathJax。物理数学の記事と同じ表示方法）

- インライン：`\( … \)`、別行立て：`\[ … \]`。`$…$` は使わない
- **等号が2つ以上つながる式変形は、別行立て `\[ … \]` で書く。** インラインに押し込むと狭い画面で読めなくなる。インラインに残してよいのは `\(f(5)=25\)` のような単発の値や記号まで
- 解答の中の式変形は、ラベルだけの段落 → 別行立ての式 → 補足は別の段落、の形にする。行末の句点「。」は落とす

```html
<p>(a)</p>
\[ (x^2)'e^{-x}+x^2(e^{-x})'=2xe^{-x}-x^2e^{-x}=x(2-x)e^{-x} \]
<p style="margin:4px 0"><span style="font-size:13.5px;color:var(--ink-faint)">補足…</span></p>
```

- 長い式は `\begin{aligned}…\end{aligned}` で折る
- 数式の中の `<` は、すぐ後ろが英字なら `&lt;` と書く（`0<a` は HTML のタグの始まりと読まれて壊れる。`0<\theta`・`h<0` はそのままでよい）
- 図の中（SVG）では MathJax は動かない。変数は `<text font-style="italic">x</text>` のように斜体の文字で書く
- 数式を使うときは、`<head>` の「数式」の読み込みと CSS のオプションを残す（§7）

### 8.3 人文・社会系

#### 出典

- **事実・数字・年号・引用には出典を付ける。** 本文の該当する文の後ろに注番号を置き、記事の末尾（最後の小節）に参考文献の一覧を置く

```html
<p>…と定められた。<span class="cite"><a href="#ref-1">[1]</a></span></p>
…
<h3>参考文献</h3>
<ol class="refs">
  <li id="ref-1">著者名『書名』出版社、出版年、ページ。</li>
  <li id="ref-2">作成者「資料名・ページ名」（公表年月日）、<a href="https://…">https://…</a> <span class="acc">（2026年11月18日閲覧）</span></li>
</ol>
```

- 注番号は本文に出てくる順に 1 から。同じ出典を2回目以降に使うときは同じ番号。一覧の `id` は `ref-1`・`ref-2`…（注番号と同じ数）
- 一覧の書き方：本は `著者名『書名』出版社、出版年、ページ。`、論文は `著者名「論文名」『誌名』巻号、出版年、ページ。`、ウェブは `作成者「ページ名」（公表年月日）、URL（閲覧日）`。英語の資料は原題のまま
- 出典は、できるだけ一次資料（法令・公的統計・原典・当事者の公表）か、査読のある研究・定評のある事典にする。ウェブの資料には閲覧日を書く
- 図表の出典は、図表のすぐ下に `<p class="src">出典：…<span class="cite"><a href="#ref-2">[2]</a></span></p>`

#### 引用

```html
<blockquote class="quote">
  <p>引用する文。原文のまま、改めずに写す。</p>
  <span class="by">― 著者名『書名』（出版年）、ページ<span class="cite"><a href="#ref-2">[2]</a></span></span>
</blockquote>
```

- 引用は原文のまま。省くときは「（中略）」、補うときは〔 〕。翻訳して引用するときは、`.by` に「（筆者訳）」と書く
- 引用は、説明に必要な最小限の長さにする（本文が主、引用が従）

#### 年表

```html
<ol class="timeline">
  <li><span class="y">1945年</span><span class="ev"><strong>出来事の名前</strong>。何が起き、なぜ重要か。<span class="cite"><a href="#ref-1">[1]</a></span></span></li>
</ol>
```

- 古い順に並べる。年が幅を持つときは「1990年代」「1990〜1995年」。月日まで要るときは本文で書く

#### 意見が分かれるテーマ（政治・政策・歴史の評価など）

- **主な立場を、それぞれの支持者が納得する形で、公平に並べる。** 同じ形（`.positions` の囲み）・同じくらいの分量で、どれかを先に・大きく・好意的に書かない。各立場の主張は、その支持者が使う言葉と、支持者が挙げる根拠で書く

```html
<div class="positions">
  <div class="pos"><span class="lab">立場 A</span><h4>立場の名前</h4><p>主張の中心と、その根拠。<span class="cite"><a href="#ref-1">[1]</a></span></p></div>
  <div class="pos"><span class="lab">立場 B</span><h4>立場の名前</h4><p>主張の中心と、その根拠。<span class="cite"><a href="#ref-2">[2]</a></span></p></div>
</div>
```

- 事実（何が起きたか、何が定められているか、統計が何を示すか）と評価（それが良いか悪いか）を分けて書く。評価の言葉（「失敗した」「成功した」）を、出典なしに筆者の声で書かない
- **筆者の意見を書く場合は、事実の説明と分けて、`box opinion`「筆者の意見」の囲みに入れる。** 「私は〜と考える」のように、意見であることが分かる書き方にする。意見の囲みは、立場を公平に並べた後に置く

```html
<div class="box opinion"><span class="lab">筆者の意見</span>
<p>私は…と考える。理由は…。</p></div>
```

#### 時間とともに変わる情報

- 制度・法律・現職者・統計・組織の名前など、時間とともに変わる情報には「**いつ時点の情報か**」を書く：`<span class="asof">2026年11月時点</span>`（文の後ろか、表の題の後ろ）
- 統計は、何年の値か（調査年）と、いつ公表されたものかを、表の題か出典の行に書く
- `.foot` に、記事全体の時点を書く（例：「制度と統計は 2026年11月時点のものです。」）

#### foot の断り書き

- `Academic Gates ／ シリーズ名 X章 章の題 ／ X-Y「節の題」。` の後に、記事全体の時点と、立場の扱い（意見が分かれるテーマを扱った記事では「主な立場を並べて紹介しています。」など）を書く

## 9. 画像

- スクリーンショット・写真は HTML の中に data URI で埋め込んでよい：`src="data:image/jpeg;base64,…"`
- **`<img>` には次の5つを必ず付ける**

```html
<figure class="fig">
  <img src="data:image/jpeg;base64,…" data-file="cyber_0-1_s05.jpg" width="1400" height="728" loading="lazy" alt="Parrot のデスクトップ。端末に、echo と printf と python3 で変換した結果が表示されている">
  <figcaption>操作した順に番号を付けています。<br>
    <strong>赤枠①</strong>：手順1。2進数・16進数を10進数に直した結果（10、255、255、65535）。</figcaption>
</figure>
```

| 属性 | 決まり |
|---|---|
| `data-file` | ファイル名。`<接頭辞>_<X-Y>_s<小節2桁>.<拡張子>`（例：`cyber_0-1_s05.jpg`）。同じ小節に2枚目からは `_2`・`_3`（例：`cyber_0-1_s05_2.png`）。受け渡しのための名前で、サイトでの置き場所と名前は組み込む側が決める |
| `width`・`height` | 画像の**実際の画素数**（縮小して表示されても、元の画素数を書く）。書かないと、読み込みのときに段組みがずれ、目次から飛んだ先がずれる |
| `loading` | `lazy` |
| `alt` | 何が写っているかを1〜2文で。札の文字をそのまま並べない |
| `src` | data URI。スクリーンショット・写真は JPEG、拡大の切り抜き・文字の細かいものは PNG |

- 大きさ：幅 1400px 前後（いまの記事は 1400×728 など）。拡大の切り抜きは `class="fig zoom"`（幅 560px まで）に入れる
- 札（赤枠と番号）：赤い枠と ①② の番号を画像に描き込む。番号は操作した順。figcaption の最初に「操作した順に番号を付けています。」、続けて `<strong>赤枠①</strong>：…` を札ごとに1行
- 人文・社会系の写真・地図・資料の画像は、自分で作ったものか、利用の条件（ライセンス）が分かるものだけを使い、figcaption に出典とライセンスを書く

### 英語版の画像（札があるとき）

- 札を描いたスクリーンショットは、**日本語の札の画像と、英語の札の画像の2種類**を作る
- 英語版の画像は、日本語版と**同じ縦横の画素数**、札の**位置・大きさ・色・形を同じ**にし、札の文字だけを英語にする（英語の文が長いときは短く訳す。札の位置を動かさない）
- ファイル名は、日本語版の名前の末尾（拡張子の前）に `_en`：`cyber_0-1_s05.jpg` → `cyber_0-1_s05_en.jpg`
- 英語の札の画像は、別のファイルとしてダウンロードフォルダに渡す（§1）。英語版の HTML を作るときは、その画像を埋め込み、`data-file` も `_en` の名前にする

## 付録D　シリーズの目次ページの形（見本：`lesson-toc-template.html`）

目次ページは、サイトの担当が `<接頭辞>_series.md` から作る（記事を書く側は作らない）。どう表示されるかを知るための見本。

- PC（769px 以上）：左に部・章の見出しと節の行、右にプレビュー（スクロールしても見える位置に固定）
  - 行：`番号　題　説明の一行`（入りきらない分は「…」）。公開した節はリンク、まだの節は破線で右端に「準備中」
  - プレビュー：行にカーソルを合わせるかフォーカスすると、その節の「部 ／ 章」・番号・題・説明の全文・公開中／準備中、公開済みなら「この節で学ぶこと」（記事の目次レールの項目。§5）と「読む →」。何も選んでいないときは、最初に読む節を「ここから読む」として出す
- スマホ（768px 以下）：プレビューは出ない。行は2段（番号と題／説明は2行まで）
- 部・章・節の数は出さない（§11）

```html
<div class="toc-layout" data-unit="節">                  <!-- 英語版は section、記事を「記事」と呼ぶシリーズは 記事 -->
  <div class="toc-layout__list">
    <section class="toc-part" aria-labelledby="part-1">    <!-- 部の無いシリーズは .toc-part を使わず、.toc-ch を並べて章を h2 に -->
      <div class="toc-part__head"><span class="toc-part__no">部 I</span><h2 id="part-1">部の題</h2></div>
      <section class="toc-ch">
        <h3>1章 章の題</h3>
        <p class="toc-ch__lead">章の説明（任意）</p>
        <ol class="toc-list">
          <li><a class="toc-row" href="prefix_1-1.html"><span class="toc-row__no">1-1</span><span class="toc-row__title">題</span><span class="toc-row__desc">説明の一行</span></a></li>
          <li><div class="toc-row"><span class="toc-row__no">1-2</span><span class="toc-row__title">題</span><span class="toc-row__desc">説明の一行</span></div></li>
        </ol>
      </section>
    </section>
  </div>
  <aside class="toc-preview"></aside>                     <!-- 中身は js/toc-preview.js が作る -->
```
