1-1　パケットとIP通信で実際に起きていること

PC（Personal Computer：パーソナルコンピューター）同士の通信は、小さな「荷物」に分けて送られています。この荷物＝パケットと、その宛先＝IPアドレス。この2つを押さえると、以降で学ぶスキャン・パケット解析・攻防のすべての土台ができます。

この節ではまず概念を押さえ、そのあと Kali と Parrot で実際にコマンドを打って、パケットの「送信元→宛先」を自分の目で確認します。攻撃も防御も、まずは「通信の中で何が起きているか」を見えるようにするところから始まります。

読み方：コマンドは、右端のコピーボタン（重なった四角のアイコン）でコピーできます。各コマンドの下に、全パーツの意味と出力の読み方を載せています。

§01

パケット — 通信は荷物に分かれる

この節で押さえること
  • データは一度に丸ごとではなく、小さなパケット（荷物）に分割して送られる。
  • 分ける理由は、回線の共有・失敗への強さ・扱いやすさ。
  • パケットは ヘッダ（宛先などの情報）＋ペイロード（中身） でできている。

PC同士がデータをやり取りするとき、データは一度に丸ごと送られるのではなく、小さな荷物に分割して送られます。この荷物1つ1つを パケット と呼びます。

分厚い本を郵送する場面を想像してください。本をそのまま1個の塊で送るのではなく、ページを束ねて複数の封筒に分け、それぞれに宛先を書いて送り、相手側で組み立て直す——ネットワークもこれと同じことをしています。

なぜ分けるのか。理由は3つあります。

  • 回線をみんなで共有できる：1つの大きな通信が回線を独占しない。
  • 失敗に強い：途中で1個失くしても、その1個だけ送り直せばいい。
  • 扱いやすい：小さい単位のほうが中継機器も処理しやすい。
誰が送り直し・並べ直しをするのか

「失くした1個を送り直す」「届いた順を正しく並べ直す」のは、実はこのあと §02 で学ぶ IP の仕事ではありません。それを引き受けるのは、IP の上で動く TCP（Transmission Control Protocol：伝送制御プロトコル）です（1-2 で扱います）。プロトコルとは、「通信をこういう手順・形式でやりましょう」という約束ごと（規格）のことです。ここでは「分けておくと、そういう対処ができるようになる」と押さえておけば十分です。

各パケットは、ざっくり ヘッダ＋ペイロード の構造です。ヘッダには「どこから・どこへ」といった配送情報が、ペイロードには運びたい中身が入っています。実際には、封筒の中にさらに封筒が入ったような入れ子になっていて（Ethernet → IP → ICMP や TCP …）、それぞれの層が自分のヘッダを持ちます。ここに並んだ名前は、どれもプロトコルの名前です（Ethernet は有線LANの規格で §03、IP は §02、ICMP は §04、TCP は 1-2 で扱います）。この全体像は 1-4 の階層モデルで整理します。この節で扱うのは、そのうち「どこから・どこへ」を担う IP の層です。

§02

IPアドレス — 荷物の宛先

どの封筒にも宛先の住所が書いてありますよね。パケットの世界で、この住所にあたるのが IPアドレス です。そして、住所を見てパケットを宛先まで届ける仕組みが IP（Internet Protocol：インターネット・プロトコル） です。

IPアドレスには2種類ある：IPv4 と IPv6

IPv4（Internet Protocol version 4：IP の第4版。読み方はアイピー・ブイフォー）は、192.168.128.2 のように 0〜255 の数字を4つ、ドットで区切って書く住所です。全部で32ビット（0か1が32個並んだもの）で表され、作れる住所は約43億通り。インターネットの初期から使われてきた、いちばん目にする形です。

ところが、インターネットにつながる機器が増えて約43億通りでは足りなくなりました。そこで作られたのが IPv6（Internet Protocol version 6：IP の第6版。読み方はアイピー・ブイシックス）です。128ビットで表され、事実上使い切れないほどの数があります。書き方も違い、fd89:34fc:700e:a388:… のように、0〜9 と a〜f を使った数（16進数）をコロン : で区切って書きます。

いまは両方が同時に使われていて、1つのインターフェースが IPv4 と IPv6 の住所を両方持っていることもよくあります（Kali も Parrot もそうなっています）。この講座では、読みやすく、演習の通信でも使う IPv4 を中心に扱います。

ちなみに 192.168.○.○ は、家庭や社内などの内部ネットワーク用に取っておかれた範囲（プライベートアドレス）です。インターネット上の住所とはぶつからないので、どの家庭でも同じ番号を使えます。

ただし、プライベートアドレスのままではインターネットに出られません。そこで、内部ネットワークの出入口にあるルーター（ネットワークどうしをつなぎ、パケットを中継する機器）が、送信元の住所をインターネット用の住所に書き換えて送り出します。この仕組みを NAT（Network Address Translation：ネットワークアドレス変換）といいます。家庭のルーターが毎日やっていることで、IPv4 不足を補う工夫の1つでもあります。この演習では、Parrot の外部用インターフェースが UTM（この講座で仮想マシンを動かしている Mac のソフト）の NAT を通ってインターネットにつながっています。

ここで1つ大事な点があります。IPアドレスは「マシン（PC）」ではなく、マシンについているネットワークの出入口＝インターフェース（interface）ごとに付きます。インターフェースの実体は、NIC（Network Interface Card：ネットワーク・インターフェース・カード）と呼ばれる通信用の部品で、LANケーブル（LAN：Local Area Network＝構内ネットワーク）や Wi-Fi につながる「口」です。仮想マシンの場合は、UTM が作った仮想の NIC が付いています。NIC は1台に何枚でも付けられるので、1台が複数の住所を持てます。この演習環境では次のようになっています。

マシンインターフェースIPアドレス用途

末尾の「/24」とは

アドレスの後ろの /24 は、どこまでが「同じネットワーク」かを表す書き方です。/24 なら、192.168.128.○ の ○ だけが違うアドレスどうしが同じネットワークになります。Kali（.2）と Parrot（.3）は同じ 192.168.128.○ なので、ルーターを通さずに直接やり取りできます。

なぜ「24」なのか：IPv4 アドレスは全部で 32ビット（0 と 1 が32個並んだもの）で、ドットで区切った4つの数字が、それぞれ 8ビットずつを表しています。/24 は「先頭の24ビット＝最初の3つの数字（192.168.128）がネットワークの名前」という意味です。8×3＝24 なので、ドットの区切りとぴったり合って読みやすくなります。

決まった値なのか：決まってはいません。ネットワークを作る人が、用途に合わせて決めます。/24 は家庭や小さなオフィスで最もよく使われる値です。○ の部分は 0〜255 の256通りで、0 と 255 は特別な用途に使うため、機械に割り当てられるのは 1〜254 の254台。たいていの小さなネットワークには十分な数です。台数が多いなら /16（192.168.○.○、約6万5千台）のように広げ、逆に /25 や /30 のように細かく区切ることもあります。今回の /24 は、UTM が作った仮想ネットワークの設定によるものです。

ちなみに §03 で出てくる lo の 127.0.0.1/8 は「最初の1つの数字（127）だけがネットワーク」という意味で、127.○.○.○ はすべて自分自身を指します。範囲の計算方法（サブネット）は後の章で詳しく扱います。

IP は「ベストエフォート」

IP には大事な性質があります。届けられるなら届けるが、確実に届いたか・順番通りかは保証しない——郵便でいう「投函はするが、到達も順序も保証しない」状態です。

この足りない部分は、TCP を使う通信なら TCP が補います（1-2）。ただし、すべての通信が TCP を使うわけではありません。§04 で使う ping（ICMP）は TCP を使わないので、届かなければそのまま「パケットロス」として失われます。

小さな学びポイント：eth1 と enp0s2、名前が違う理由

同じ内部ネットワークなのに、Kali は eth1、Parrot は enp0s2 と名前が違います。どちらも Debian 系（Debian という Linux をもとに作られた仲間）で、名前を付ける仕組みも同じ systemd / udev（Linux で、起動の流れや、つながっている部品の認識を受け持つ仕組み）です。違うのは設定で、Kali 側は昔ながらの ethX 方式、Parrot 側は「予測可能な名前」方式を使っています。

この切り替えは、カーネルパラメータ net.ifnames=0 などで行われます。カーネルは OS（Operating System：基本ソフト）のいちばん中心にあって、ハードウェア（部品）とソフトウェアの橋渡しをする部分です。カーネルパラメータは、そのカーネルに起動するときに渡す設定スイッチのことで、net.ifnames=0 は「予測可能な名前を使わない（＝ethX にする）」という意味のスイッチです。

2つの名前は、末尾の数字の意味も違います。

  • eth1 ＝ eth（Ethernet の略）＋「1」＝見つかった順番（0番目、1番目…）
  • enp0s2 ＝ en（Ethernet）＋ p0（PCI バス0番。PCI＝Peripheral Component Interconnect：周辺機器をつなぐ規格）＋ s2（スロット2番）。差さっている位置から付く名前

ここで出てきた言葉の意味です。

  • Ethernet（イーサネット）：LANケーブルなどでつなぐ、有線LANの通信規格。いちばん普及している LAN の方式です。
  • PCI バス：PC の中で、マザーボード（中心の基板）と NIC などの部品をつなぐデータの通り道の規格。
  • スロット：その通り道に部品を差し込む差込口。何番の差込口に差さっているかが、名前の数字になります。

仮想マシンの場合は、本物の基板ではなく、UTM が用意した仮想の PCI スロットに仮想 NIC が差さっている、という扱いになります。

なので eth1 の「1」と enp0s2 の「2」は対応していません。予測可能な名前が作られたのは、ethX の順番が起動のたびに入れ替わることがあり、「eth0 だと思っていたら別のNICだった」という事故が起きたからです。

確かめたい人は、Kali で次を実行し、表示の中に net.ifnames=0 が含まれているか見てみてください。

cat /proc/cmdline

cat はファイルの中身を表示するコマンド。/proc/cmdline は、カーネルが起動するときに受け取ったカーネルパラメータが書かれた特別なファイルです。

§04

パケットを観察する

次に、パケットに「送信元→宛先」の住所が実際に書かれていることを、自分の目で確認します。ここでは ping を使います。ping は相手に「いますか？」と小さなパケットを送り、相手が「いますよ」と返すことで、通信が届くかを確かめる道具です。

このとき使われるのが ICMP（Internet Control Message Protocol：インターネット制御メッセージプロトコル）です。データを運ぶためではなく、「届かなかった」「いますか？／いますよ」といった通信の状態を知らせ合うための連絡用プロトコルで、IP とセットで使われます。ping の「いますか？」は ICMP の echo request、「いますよ」は echo reply という種類のメッセージです。

ping に返事がない ≠ 相手がいない

ICMP はファイアウォール（決めたルールに従って、通信を通すか止めるかを判断する門番の仕組み）で止められていることがよくあります（たとえば Windows は、既定では ping に応答しない設定のことが多い）。そのため「返事がない」は「相手がいない」とは限りません。この性質は、4章の「ホスト発見」で大きく効いてきます。今回の Parrot は ICMP を止めていないので、返事が返ってきます。

これを Kali で観察します。Kali の端末を2つ開いて並べ、片方でパケットを見張りながら、もう片方で ping を送ります。Parrot 側では何も打ちません（返事は自動で返ります）。

コマンドの分解
部分意味
ping相手に ICMP の echo request を送り、echo reply が返ってくるかを確かめる。名前は、潜水艦のソナー（音で相手を探る装置）の「ピーン」という音に由来すると言われる。

IPIP のパケットであること。

ICMP中身のプロトコルが ICMP であること（§04 冒頭）。

端末B（ping）の読み方

出力例PING 192.168.128.3 (192.168.128.3) 56(84) bytes of data. 64 bytes from 192.168.128.3: icmp_seq=1 ttl=64 time=1.81 ms ... 4 packets transmitted, 4 received, 0% packet loss, time 3042ms rtt min/avg/max/mdev = 0.346/0.840/1.811/0.591 ms
部分意味
PING 192.168.128.3 (192.168.128.3)これから ping を送る宛先。カッコ内は実際に使う IP アドレス。宛先を名前（例：example.com）で指定したときは、ここに変換後の IP アドレスが出る。
56(84) bytes of data1回に送るデータは56バイト。カッコ内の84は、IPヘッダ20＋ICMPヘッダ8を足した、パケット全体の大きさ。
64 bytes from 192.168.128.3返ってきた reply の大きさ（データ56＋ICMPヘッダ8）と、返事をくれた相手。
icmp_seq=1ここから3つは「名前=値」の形。icmp_seq（ICMP の sequence＝順番）が 1、つまり1回目の往復。tcpdump の seq と対応する。
ttl=64ttl は TTL（Time To Live：生存時間）の略で、パケットの寿命を表す数。ルーターを1つ通るたびに1ずつ減り、0 になると捨てられる（迷子のパケットが永遠に回り続けないため）。Linux は64から始めることが多く、今回は同じネットワーク内で直接届いたので減らずに64。
time=1.81 ms往復にかかった時間。ms はミリ秒（1000分の1秒）。1回目だけ少し遅いのは、相手の機械の番号を調べるやり取り（下の ARP）などが最初に入ることがあるため。
4 packets transmitted, 4 received, 0% packet loss送った数（transmitted）・返ってきた数（received）・失われた割合（packet loss）。4回送って4回とも返ってきた。
time 3042ms全体でかかった時間（約3秒）。1秒おきに4回送るので、1回目から4回目までの間隔は3つ分＝約3秒になる。
rtt min/avg/max/mdev往復時間（rtt：round-trip time）の最小（min）／平均（avg）／最大（max）／ばらつきの大きさ（mdev）。mdev は mean deviation（平均偏差）の略という名前だが、Linux の ping が実際に計算しているのは標準偏差（値が平均からどれくらい散らばっているかを表す数）。後ろの 0.346/0.840/1.811/0.591 ms が、同じ順番での値。

「ping 1回＝2パケット」は ICMP だけを数えた話

今回は icmp フィルタで ICMP だけを表示しているので、きれいに「往復＝2個」に見えます。実は、最初の ping の前には、相手の機械の番号（MACアドレス。MAC＝Media Access Control：媒体アクセス制御。NIC ごとに付いている、機器そのものの番号）を調べる ARP（Address Resolution Protocol：アドレス解決プロトコル）というやり取りが起きることがあります（まだ相手を知らないとき）。フィルタを外して sudo tcpdump -i eth1 -n で試すと見えることがあります。ARP は 8-1 で詳しく扱います。

この節の核心

IP パケットのヘッダには、送信元IPと宛先IPが書かれています。だから受け取った側は「どこから来た（と名乗っている）か、どこ宛てか」を読み取れます。

ただし、送信元IPは送り手の自己申告です。送り手が偽の送信元を書くこと（IPスプーフィング。spoofing：なりすまし）も、途中のルーターなどが書き換えること（NAT：Network Address Translation＝ネットワークアドレス変換。§02 参照。家庭のルーターを通ると、送信元はルーターの住所に置き換わる）もありえます。「送信元IP＝本当の送り主」とは限らない——この前提は、攻撃を理解するうえでも、ログを見て防御するうえでも、ずっと大事になります。

この節で押さえた土台を整理します。

  • パケット＝通信を分割した“荷物”。ヘッダ＋ペイロードの入れ子でできている。
