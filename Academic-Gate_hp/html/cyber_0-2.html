0-2　文字とデータの表し方文字も改行もファイルも、中身はバイトの並び

画面に「A」や「あ」と表示されていても、コンピューターの中にあるのは バイトの並びだけです。文字を番号に置きかえる表（文字コード）があるので、バイトを文字として読めます。

この節では、英字のための文字コードと、日本語も扱える今の標準の文字コードを学び、Parrot の端末で文字・改行・ファイルの中身を16進数のままのぞきます。最後に、2バイト以上の数の並べ方（エンディアン）と、ファイルの先頭にある「形式の印」を確かめます。

§01

文字コード — 文字に番号を付ける

この節で押さえること
  • 文字は、文字コードという対応表で番号に置きかえて保存・送信される。
  • 英字・数字・記号は1文字1バイト。日本語は、今の標準の文字コードで多くが3バイト。
  • 改行は Windows が 0d 0a、Linux が 0a。見た目は同じでもバイトがちがう。
  • 2バイト以上の数は、ネットワークでは大きい桁から（ビッグエンディアン）並べる。

0-1 で学んだように、コンピューターが扱えるのは 0 と 1 の並び、つまり数だけです。では、文字はどうやって保存しているのでしょうか。

答えは、「この文字はこの番号」という対応表を決めておき、文字を番号に置きかえることです。この対応表を文字コードと言います。番号さえ決まれば、あとは 0-1 のやり方で16進数やビットにできます。

P1文字は、対応表（文字コード）で番号に置きかえて扱う原理 ― 覚える

どんな決まりか：約束。どの文字にどの番号を付けるかは、規格で決めた表による。書く側と読む側が同じ表を使う前提で成り立つ。

由来：電信の時代から、文字を符号（モールス信号など）に置きかえて送る考え方があり、コンピューターでも同じ方法がとられた。

§02

ASCII — 英字・数字は1バイト

英字・数字・記号のための、いちばん基本の文字コードが ASCII（American Standard Code for Information Interchange：情報交換用米国標準コード）です。今使われている文字コードのほとんどは、ASCII と同じ番号を引き継いでいます。

P2ASCII：英字・数字・記号と制御文字に、0〜127 の番号を付けた表原理 ― 覚える

どんな決まりか：規格。1963年にアメリカの規格（ASA X3.4。今の ANSI（American National Standards Institute：米国国家規格協会））として定められた。

由来：電信のテレタイプ（タイプライター式の通信端末）のための符号を整理して作られた。改行などの「制御文字」が入っているのはそのため（§03）。

番号は 0〜127 の 128 通りなので、0-1 の D1（n ビットで 2ⁿ 通り）から 2⁷＝128、つまり 7ビットで足ります。コンピューターは1バイト（8ビット）単位で扱うので、ASCII の文字は1文字が1バイトになり、いちばん上のビット（ビット7）はいつも 0 です。

D1ASCII の文字は1文字1バイト（0x00〜0x7f）導出 ― 自分で導ける

使う原理：P2、0-1 の D1（2⁷＝128）と P3（1バイト＝8ビット）

導き方：128 通りは 2⁷ なので7ビットで表せる。1バイト＝8ビットに入れると、いちばん上のビットは 0 で、範囲は 00000000〜01111111＝0x00〜0x7f。

だから：バイトの値が 0x80 以上なら、それは ASCII の文字ではない（日本語の UTF-8 などの一部か、文字ではないデータ）。

表をよく見ると、大文字と小文字の番号には決まった差があります。

D2大文字と小文字の番号の差は、いつも 32（0x20）導出 ― 自分で導ける

使う原理：P2、0-1 の P2（桁の重み）

導き方：A＝0x41＝01000001、a＝0x61＝01100001。ちがうのはビット5 だけで、その重みは 2⁵＝32＝0x20。A〜Z と a〜z は同じ順番で並んでいるので、どの文字でも差は 32。

たとえば G＝0x47 なら、g＝0x47＋0x20＝0x67。

§03

改行 — CR と LF

ASCII の 0x00〜0x1f は、画面に表示しない制御文字です。その中で最もよく出てくるのが改行です。改行には、CR と LF という2つの制御文字が関わります。CR・LF は名前を略したもので、アルファベット2文字が入っているわけではありません。どちらも、中身は1バイトの制御文字1つです（CR＝0x0d、LF＝0x0a）。

P3改行の書き方は、OS（Operating System：基本ソフト）や規格ごとに決まっている原理 ― 覚える

どんな決まりか：慣習と規格。Linux・macOS は、改行を制御文字 LF だけ（1つ＝1バイト：0a）で表す。Windows は、制御文字 CR と LF を続けて（2つ＝2バイト：0d 0a）表す。HTTP やメールなどの通信の規格も CR LF と定めている。

由来：テレタイプでは、印字する位置を左端へ戻す動き（CR：Carriage Return＝復帰）と、紙を1行送る動き（LF：Line Feed＝改行）が別々だった。どちらで「改行」を表すかを、OS ごとに別々に決めたまま今に至る。

同じ「2行の文章」でも、Windows 式と Linux 式では、改行の分だけバイト数が変わります。§06 の手順3 で、実際にファイルを作って確かめます。

D3改行1つは、Windows 式で2バイト、Linux 式で1バイト導出 ― 自分で導ける

使う原理：P3・D1

導き方：CR も LF も ASCII の制御文字1つなので、それぞれ1バイト（D1）。Windows 式は CR と LF の2つで2バイト、Linux 式は LF 1つで1バイト。line1（5文字）＋改行 が2行なら、5×2＋2×2＝14 バイトと 5×2＋1×2＝12 バイト。

C1見た目が同じファイルでも、中身のバイトはちがうことがある言えること ― 説明できる

根拠：D3

画面に表示すると同じ文章でも、改行の書き方がちがえばバイト数も中身も変わる。ファイルが同じかを確かめるときは、表示ではなくバイトで比べる（14章のハッシュ値は、1バイトちがうだけで全く別の値になる）。1-4 で出てくる HTTP のやり取りも、規格どおり各行の最後が 0d 0a になっている。

§04

UTF-8 — 日本語は3バイト

ASCII は 128 通りしかないので、日本語のような文字は入りません。そこで、世界中の文字に番号を付けた表と、その番号をバイトにする方式が作られました。

P4Unicode は世界中の文字に番号を付けた表、UTF-8 はその番号をバイトの並びにする方式原理 ― 覚える

どんな決まりか：規格。Unicode（最初の版は1991年）は「あ」を U+3042 のように、U+ と16進数の番号で表す。UTF-8（Unicode Transformation Format 8-bit：ユニコードの8ビット単位の符号化方式）は、番号の大きさに応じて1〜4バイトを使う。今の Web やLinux の標準。

由来：UTF-8 は1992年にケン・トンプソンとロブ・パイクが考案し、今の規格は RFC（Request for Comments：意見募集）3629（2003年）。ASCII の範囲をそのまま1バイトで書けるように作られたので、ASCII だけの文章は UTF-8 としてもそのまま読める。

「あ」の番号 U+3042 は、表の3段目（U+0800〜U+FFFF）に入るので3バイトになります。3バイトの中身は、0-1 の2進数と16進数の計算で導けます。

D4「あ」（U+3042）は UTF-8 で e3 81 82導出 ― 自分で導ける

使う原理：P4・0-1 の D4（4ビット＝16進数1桁）

導き方：① 0x3042 を16進数1桁ずつ4ビットにして 0011 0000 0100 0010。② 3バイトの形 1110xxxx 10xxxxxx 10xxxxxx の x に、左から4・6・6ビットずつ入れて 11100011 10000001 10000010。③ 4ビットずつ16進数にして e3 81 82。

番号の範囲が変われば：2バイトの範囲（U+0080〜U+07FF）なら、11ビットを5・6ビットに分けて 110xxxxx 10xxxxxx に入れる（問10）。

日本語には、UTF-8 より前から使われている Shift_JIS（シフトJIS）という文字コードもあり、そちらでは「あ」は 82 a0 の2バイトです。表がちがえば、同じ文字でもバイトがちがいます。逆に言えば、同じバイトでも、読む表がちがえば別の文字になります。

D5文字化けは、書いたときと別の表でバイトを読むと起きる導出 ― 自分で導ける

使う原理：P1・P4

導き方：文字コードは「書く側と読む側が同じ表を使う」前提の約束（P1）。UTF-8 で書いた e3 81 82 を Shift_JIS の表で読めば別の文字になり、Shift_JIS の 82 a0 を UTF-8 で読めば、82 が先頭に来てはいけない形（10xxxxxx）なので読めない（�）。

だから：文字化けしても、バイトそのものはこわれていない。正しい表で読み直せば元に戻る。

C2文字数とバイト数は、同じとは限らない言えること ― 説明できる

根拠：D1・D4

ASCII の文字は1文字1バイトだが、UTF-8 の日本語は1文字3バイト。「10文字まで」と「10バイトまで」は別の制限になる。入れ物の大きさはバイトで決まるので、文字数だけで確かめると入りきらないことがある（12章のバッファオーバーフローにつながる話）。

計算ドリル（§04・全3問）

問4再現：D4「い」の番号は U+3044 である。UTF-8 の3バイトを16進数で答えよ。

自分の答えを出してから

使う：P4・D4

① 0x3044 ＝ 0011 0000 0100 0100

② 4・6・6ビットに分けて 0011 ／ 000001 ／ 000100

③ 形に入れて 1110 0011 ／ 10 000001 ／ 10 000100 → e3 81 84

問5応用：P4 → D4ユーロの記号「€」の番号は U+20AC である。本文で扱っていない文字だが、UTF-8 で何バイトになり、16進数で何になるか。

自分の答えを出してから

使う：P4（UTF-8 の決まり）・D4

① 0x20AC ＝ 0010 0000 1010 1100（a＝10＝1010、c＝12＝1100）

② 4・6・6ビットに分けて 0010 ／ 000010 ／ 101100

③ 1110 0010 ／ 10 000010 ／ 10 101100 → e2 82 ac

日本語でなくても、番号の範囲で何バイトかが決まり、同じ手順でバイトを導けます。

問6応用：D1・D4 → C2(a) 「あいう」は何文字か。UTF-8 で何バイトか。Shift_JIS では1文字2バイトとして何バイトか。(b) 「Aあ」は UTF-8 で何バイトか。(c) 入力欄に「10バイトまで」の制限があるとき、UTF-8 の日本語は最大何文字入るか。

自分の答えを出してから

使う：D1・D4・C2

(a) 3文字。UTF-8 は 3×3 ＝ 9 バイト、Shift_JIS は 3×2 ＝ 6 バイト。

(b) A は ASCII の範囲で1バイト（D1）、「あ」は3バイト（D4）なので 4 バイト。

(c) 3バイトずつなので、3文字で9バイト、4文字では12バイトで超える。3文字（1バイト余る）。

「10文字まで」と「10バイトまで」では、入る日本語の数が3倍以上ちがいます（C2）。

§05

16進ダンプの読み方

ファイルやデータの中身を、1バイトずつ16進数2桁で並べて表示したものを16進ダンプ（hex dump）と言います。文字として表示できないバイト（改行や、文字ではないデータ）も、16進数ならすべて見えます。この講座では xxd というコマンドを使います。

xxd の1行には16バイト分が入り、左端のオフセットは16進数で 00000000、00000010（＝16）、00000020（＝32）…と16ずつ増えます。0-1 の16進数の読み方が、そのまま使えます。

16進ダンプが出てくる場面

6章ではパケットの中身を、14章ではマルウェアの疑いがあるファイルの中身を、16進ダンプで調べます。Wireshark などの解析ツールも、画面の下に同じ形の16進ダンプを表示します。

計算ドリル（§05・全1問）

問7再現：16進ダンプ100 バイトのファイルを xxd で表示した。(a) 何行になるか。(b) 最後の行の左端のオフセットは16進数でいくつか。その行には何バイトあるか。

自分の答えを出してから

使う：0-1 の P2（16進数の桁の重み）

(a) 1行16バイトなので、100÷16 ＝ 6 余り 4。16バイトの行が6行と、4バイトの行が1行で 7 行。

(b) 7行目は 16×6 ＝ 96 バイト目から始まる。96 ＝ 6×16¹＋0×16⁰ ＝ 0x60 なので 00000060。その行には 4 バイト。

§06

ここからは Parrot の端末で、§02〜§05 で学んだことを確かめます。通信は行いません。端末を1つ開き、clear してから始めます。

§07

実行ファイルの先頭とエンディアン（Parrot）

最後に、文字ではないデータのバイトを見ます。1つ目は、プログラムのファイルの先頭。2つ目は、2バイト以上の数の並べ方です。

手順4：実行ファイルの先頭16バイト

COMMANDls コマンドのファイルの先頭16バイトを見る
head -c 16 /bin/ls | xxd
COMMANDls コマンドのファイルの種類を判定する
file /bin/ls
コマンドの分解
部分意味
headファイルの先頭（head）だけを出すコマンド。
-c 16-c は bytes。先頭の 16 バイトだけを出す。xxd のちょうど1行分にするため 16。
/bin/lsいつも使う ls コマンドの本体のファイル（/bin は基本のコマンドが置かれる場所）。文字ではなく、CPU（Central Processing Unit：中央処理装置）が実行する命令が入っている。
出力例00000000: 7f45 4c46 0201 0100 0000 0000 0000 0000 .ELF............ /bin/ls: ELF 64-bit LSB pie executable, ARM aarch64, version 1 (SYSV), dynamically linked, …

先頭の 7f 45 4c 46 を ASCII の表で読むと、表示できない DEL（0x7f）と E L F です。これは、このファイルが ELF 形式の実行ファイルであることを示す決まった印です。

P5ファイルの形式ごとに、先頭に置く決まったバイト（マジックナンバー）がある原理 ― 覚える

どんな決まりか：規格。ファイル形式の規格が、先頭の数バイトを決めている。ELF（Executable and Linkable Format：実行・リンク可能形式。Linux の実行ファイルの形式）は 7f 45 4c 46。

由来：ファイル名の拡張子は人が自由に付けられるので、中身の形式をソフトが確かめられるように、ファイル自身の先頭に印を書くようになった。file コマンドは、このような印の一覧（magic）を使って判定している。

D67f 45 4c 46 は「.ELF」と読め、続く 02 01 01 00 は 64ビット・リトルエンディアン・版1・System V 型導出 ― 自分で導ける

使う原理：P5・D1・0-1 の D4

導き方：0x45・0x4c・0x46 は 0x7f 以下なので ASCII の文字（D1）で、表から E L F。0x7f は制御文字の DEL なので .。5〜8バイト目は ELF の規格で意味が決まっていて、file の表示「64-bit LSB … version 1 (SYSV)」と1対1で対応する（LSB＝Least Significant Byte：最下位バイトが先＝リトルエンディアン。System V は、1980年代の UNIX（Linux の元になった OS の系統）の版の名前）。

ほかの形式にも、それぞれの印があります。

C3ファイルの種類は、名前（拡張子）ではなく中身で見分ける言えること ― 説明できる

根拠：P5・D6

請求書.pdf という名前でも、先頭が 7f 45 4c 46 なら中身は実行ファイル。メールの添付ファイルなどで拡張子を偽るのは、マルウェアのよくある手口。file コマンドや16進ダンプで先頭を確かめれば見破れる（14章の静的解析）。

手順5：2バイトの数の並べ方（エンディアン）

P62バイト以上の数の並べ方（エンディアン）は2通りあり、ネットワークでは大きい桁から並べる原理 ― 覚える

どんな決まりか：規格と設計。大きい桁から並べるのがビッグエンディアン、小さい桁から並べるのがリトルエンディアン。TCP/IP（Transmission Control Protocol / Internet Protocol：インターネットの通信の規格群）では、数はビッグエンディアンで送ると決まっている（ネットワークバイトオーダー。IPv4（Internet Protocol version 4：インターネット・プロトコル第4版）の RFC 791 の付録など）。CPU はどちらかを設計で選び、今のパソコンの x86-64（インテルや AMD の64ビット CPU の方式）や、Parrot の ARM64（Arm 社が設計した64ビット CPU の方式。スマートフォンや Apple の M シリーズの Mac も同じ系統）は、リトルエンディアンで使われている。

由来：名前は、ダニー・コーエンの1980年の文書が、『ガリバー旅行記』で卵を大きい端（big end）から割るか小さい端（little end）から割るかで争う国々にたとえたことから。

COMMAND8080 を2バイトで、ビッグとリトルの2通りに並べる
python3 -c "print((8080).to_bytes(2,'big').hex(), (8080).to_bytes(2,'little').hex())"
COMMANDこの CPU の並べ方を調べる
lscpu | grep -i endian
コマンドの分解（python3 -c は 0-1 §05）
部分意味
(8080).to_bytes(2,…)8080 を 2バイトのバイト列に変える（Python の命令）。ポート番号と同じ2バイト。
'big' ／ 'little'並べ方。ビッグエンディアン／リトルエンディアン。
.hex()バイト列を16進数の文字で表示する。
lscpuCPU の情報を表示するコマンド（list CPU）。
grep -i endiangrep は、指定した言葉を含む行だけを取り出すコマンド。-i は大文字・小文字を区別しない（ignore case）。出力の「Endian」を含む行だけを見る。
出力例1f90 901f Byte Order: Little Endian
出力の読み方
部分例意味
1つ目1f90ビッグエンディアン。8080＝0x1f90 の大きい桁 1f が先。
2つ目901fリトルエンディアン。小さい桁 90 が先。同じ 8080 でも、バイトの順番が逆。
Byte OrderLittle EndianParrot の CPU（ARM64）は、メモリの中でリトルエンディアンで数を並べている。
D78080 はビッグエンディアンで 1f 90、リトルエンディアンで 90 1f導出 ― 自分で導ける

使う原理：P6・0-1 の D4

導き方：8080 ＝ 1×16³＋15×16²＋9×16¹＋0×16⁰ ＝ 0x1f90。2バイトに分けると大きい桁の 1f と小さい桁の 90。ビッグは大きい桁から 1f 90、リトルは小さい桁から 90 1f。

並べ方を取りちがえると：90 1f をビッグとして読めば 0x901f＝36895 になり、別のポート番号に見えてしまう。

C4パケットの数はビッグエンディアンで読み、自分の CPU の中では逆に並んでいることがある言えること ― 説明できる

根拠：P6・D7

パケットの中のポート番号や IP アドレスは、ネットワークバイトオーダー（ビッグ）で入っている。1-4 で出てくるパケットの16進ダンプも、大きい桁から読めばよい。一方、リトルエンディアンの CPU のメモリの中では逆順なので、プログラムは送る前に並べ替えている。12章でメモリの中身を見るときは、数が逆順に見えることに注意する。

演習で作った2つのファイルは消しておきます。

rm は remove（ファイルを消す）。ごみ箱を通らずにすぐ消えるので、ファイル名をよく確かめてから実行します。

問8再現：D7ポート番号 443（HTTPS（Hypertext Transfer Protocol Secure：暗号化した HTTP）で使う番号）を2バイトにしたとき、ビッグエンディアンとリトルエンディアンでそれぞれどう並ぶか、16進数で答えよ。

問9応用：P5 → D6 → C3次の3つのファイルの先頭4バイトを見た。図2 の ASCII の表を使って、それぞれ何の形式か答えよ。また、(c) は開いてよいか。

§08

セキュリティで文字コードが関わる場面

文字コードのしくみは、攻撃と防御の両方に関わります。ここでは、この先の章で出てくる3つの場面を、原理だけ見ておきます。

C5暗号化していない文字の通信は、16進ダンプでそのまま読める言えること ― 説明できる

根拠：D1・P4

ASCII や UTF-8 の文字は、決まった表で決まったバイトになるだけで、隠す働きはない。暗号化していない HTTP やメールの通信を途中で記録すれば、パスワードも文章もそのまま読める。だから重要な通信は暗号化する（7-2・7-3）。

2つ目は、見た目がそっくりな別の文字です。

C6見た目が同じでも番号がちがう文字で、本物そっくりの偽の名前が作れる言えること ― 説明できる

根拠：P4・D4

ラテン文字の e（65）とキリル文字の е（d0 b5）は画面では同じに見えるが、コンピューターにとっては別の文字。これを混ぜると、本物とそっくりに見える偽のドメイン名（Web サイトの名前）が作れてしまう。リンクを押す前に表示をよく確かめる、ブックマークから開く、などで防ぐ（3-3 のフィッシング）。ブラウザは、こうした名前を xn-- で始まる別の表記で示すことがある。

C7同じ文字を別の書き方（エンコード）で書けるので、そのまま比べるとチェックをすり抜けることがある言えること ― 説明できる

根拠：P1

たとえば Web のアドレス（URL：Uniform Resource Locator＝Web 上の場所を表す書き方）では、/ を、16進数を使った %2f という書き方でも表せる。入力のチェックが「/ という文字があるか」だけを見ていると、%2f と書かれたものを見のがす。だから、入力は元の文字に戻してからチェックする（11章）。

応用問題（§08・全1問）

問10応用：P4 → D4 → C6キリル文字の「е」の番号は U+0435 である。(a) UTF-8 で何バイトか。(b) そのバイトを16進数で答えよ（2バイトの形は 110xxxxx 10xxxxxx）。(c) ラテン文字の e（0x65）と比べて、何が言えるか。

自分の答えを出してから

使う：P4・D4・C6

(a) U+0435 は U+0080〜U+07FF の範囲なので 2バイト（図6）。

(b) 0x0435 ＝ 0000 0100 0011 0101。2バイトの形の x は 5＋6＝11ビットなので、下の11ビット 100 0011 0101 を 5・6ビットに分けて 10000 ／ 110101。形に入れて 110 10000 ／ 10 110101 → d0 b5

(c) 見た目は同じ e でも、バイトは 65（1バイト）と d0 b5（2バイト）で全く別。文字の比較はバイトで行われるので、偽の名前は本物とは別の名前として扱われる（C6）。

3バイトの形（D4）と同じ手順で、2バイトの形にも当てはめられます。
