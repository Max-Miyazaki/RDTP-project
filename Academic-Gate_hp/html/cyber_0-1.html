サイバーセキュリティ基礎 ／ 0章 準備編：コンピューターの基礎 ／ SECTION 0-1

0-1　ビット・バイトと2進数・16進数コンピューターの数の数え方を、手で計算して身につける

通信やセキュリティの画面には、5e:f1:1e:25:27:db、192.168.128.3、「148 バイト」、ポート番号「65535」のような数字が次々に出てきます。これらはどれも、コンピューターの中のビットとバイトを、人が読みやすい形に書き直したものです。

この節では、0 と 1 だけで数を表す2進数、8ビットをまとめたバイト、バイトを短く書くための16進数を学び、Parrot の端末で実際に計算して確かめます。最後に、Parrot の MAC アドレス（MAC：Media Access Control：媒体アクセス制御）や IP アドレス（IP：Internet Protocol：インターネット・プロトコル）を「何バイトか」「どのビットが何を表すか」の目で読み直します。

§01

ビット — 0 と 1 だけで表す

この節で押さえること
  • コンピューターの中の情報は、すべて 0 と 1 の並び。この1桁がビット。
  • 2進数は各桁を2の何乗かで読む。8ビット（＝1バイト）で 0〜255。
  • 16進数は4ビットを1文字で書く。1バイト＝16進数2桁。
  • MAC アドレスは6バイト、IPv4（Internet Protocol version 4：インターネット・プロトコル第4版）アドレスは4バイト、ポート番号は2バイト。

コンピューターの中では、電気が「流れている／流れていない」、電圧が「高い／低い」のように、2つの状態だけを区別して情報を扱っています。2つの状態は、数字の 1 と 0 で書き表します。

この「0 か 1 か」の1桁をビット（bit：binary digit＝2進数の1桁）と言います。1ビットで表せるのは 0 と 1 の2通りだけですが、ビットを並べると、表せる通り数がどんどん増えます。

P1コンピューターは 0 と 1 の2つの状態だけを区別する原理 ― 覚える

どんな決まりか：設計上の約束。自然界の決まりではなく、そう作っている。

由来：2つの状態だけなら、電圧が多少ぶれても読みまちがえにくい（雑音に強い）ため、今のコンピューターはこの方式。「bit」という言葉は、シャノン（C. E. Shannon）の1948年の論文「通信の数学的理論」で広まった（名付けたのは同僚のテューキー）。

ビットが1つ増えるごとに、通り数は2倍になります。2倍を n 回くり返すことを「2 の n 乗」と言い、2ⁿ と書きます（右上の小さな数が「何回掛けるか」）。たとえば 2³ は 2×2×2＝8 です。

ビットの数計算表せる通り数
1 ビット2¹ ＝ 22 通り
2 ビット2² ＝ 2×24 通り
3 ビット2³ ＝ 2×2×28 通り
8 ビット2⁸ ＝ 2×2×2×2×2×2×2×2256 通り
16 ビット2¹⁶65,536 通り
D1n ビットで 2ⁿ 通り。最大は 2ⁿ−1導出 ― 自分で導ける

使う原理：P1

導き方：ビットを1つ足すと、それまでのすべての並びの後ろに 0 と 1 を付けられるので、通り数は2倍。1ビットの 2 通りから n 回2倍して 2ⁿ。0 から数えるので最大は 2ⁿ−1。

原理がちがったら：1桁が3つの状態を持てるなら、n 桁で 3ⁿ 通りになる。

§02

2進数 — 桁の重みで読む

ふだん使っている10進数は、0〜9 の10種類の数字を使い、桁が1つ左へ進むごとに 10 倍になります。305 は「3×100 ＋ 0×10 ＋ 5×1」です。この「その桁が表す大きさ」を桁の重みと言います。

2進数は、0 と 1 の2種類だけを使い、桁が1つ左へ進むごとに 2 倍になります。ビットの並びは、そのまま2進数として読めます。

P2位取り記数法：桁の重みは「基数の何乗か」原理 ― 覚える

どんな決まりか：数学の定義。10進数なら 10ⁿ、2進数なら 2ⁿ、16進数なら 16ⁿ（基数＝何進数かの数）。右端の桁は、どの基数でも 0 乗＝1。

由来：0 を使う10進の位取りは古代インドで生まれ、アラビア世界を経て広まった。2進数の体系的な研究はライプニッツ（1703年）。

8桁の2進数の、各桁の重みです。右端がいちばん下の桁です。

各桁の数字（0 か 1）に、その桁の重みを掛けて足します。

10進数 → 2進数：大きい重みから引いていく

逆向きは、大きい重みから順に「残りから引けるなら 1、引けないなら 0」と決めていきます。

D22進数 ⇄ 10進数の変換導出 ― 自分で導ける

使う原理：P2

導き方：2進数→10進数は、各桁の数字×その桁の重み（2 の何乗か）を足す。0 の桁は消えるので「1 の桁の重みを足す」だけ。10進数→2進数は、大きい重みから順に「残りから引けるなら 1」。

基数を変えると：16 にすれば、同じ手順で16進数の変換になる（§04 の D4）。

2進数を書くときの約束

2進数の 10 は「じゅう」ではなく「いちぜろ」と読み、値は 2 です。10進数と区別するために、プログラムなどでは前に 0b を付けて 0b1010 のように書くことがあります（§04 の 16進数の 0x と同じ考え方）。また、桁数をそろえるために左を 0 で埋めることがあります。1010 も 00001010 も同じ 10 です。

§03

バイト — 8ビットのまとまり

ビット1つでは情報が小さすぎるので、コンピューターは8ビットを1つのまとまりとして扱います。これをバイト（byte）と言います。データの大きさ、ファイルの大きさ、パケットの大きさは、ふつうバイトで数えます（たとえば 1-4 では、148 バイトのパケットが出てきます）。

P31バイト＝8ビット原理 ― 覚える

どんな決まりか：慣習（今のほぼすべてのコンピューターの約束）。

由来：1964年の IBM System/360 が8ビットのバイトを採用して広まった。それ以前は6ビットなどの機械もあったので、通信の規格書（RFC：Request for Comments：意見募集）では、まぎれのないように8ビットを「オクテット」と呼ぶ。

8ビットで表せるのは 2⁸＝256 通りなので、1バイトに入る数は 0〜255（0 から数えて 256 個）です。IPv4（Internet Protocol version 4：インターネット・プロトコル第4版）のアドレスの数字が 255 までしかないのは、数字1つが1バイトだからです（§06）。

D31バイトに入るのは 0〜255 の 256 通り導出 ― 自分で導ける

使う：D1・P3

導き方：1バイト＝8ビット（P3）なので、D1 で n＝8 として 2⁸＝256 通り。0 から数えるので最大は 255。

原理がちがったら：1バイトが6ビットの機械なら 0〜63。

ビットとバイトの単位

単位の書き方は、小文字の b がビット、大文字の B がバイトです。通信の速さはビット、ファイルの大きさはバイトで表すことが多いので、混ぜないように注意します。

書き方読み意味
b ／ Bビット ／ バイト1 B ＝ 8 b。
KBキロバイト1,000 バイト。k（キロ）は「1,000倍」。
KiBキビバイト1,024 バイト（2¹⁰）。コンピューターでは2の累乗がきりがよいので、1,024 倍で数えることもある。Linux の ls -h などは 1,024 倍で数えて「K」と表示する。
MB ／ GBメガバイト ／ ギガバイト100 万バイト ／ 10 億バイト（k・M・G はそれぞれ 1,000 倍ずつ）。ソフトによっては 1,024 倍ずつで数えて MB・GB と表示するものもあるので、表示が少しちがうことがある。
Mbpsメガビット毎秒bps（bits per second：ビット毎秒）＝1秒に送れるビット数。100 Mbps なら、8 で割って 1秒に 12.5 MB（実際には、ヘッダなどの分だけ少し減る）。
C1通信の速さ（b）とファイルの大きさ（B）は 8 倍ちがう言えること ― 説明できる

根拠：P3

100 Mbps は1秒に 12.5 MB。取りちがえると、時間や容量の見積もりが 8 倍ずれる（問5）。

問4再現：D3(a) 3バイトは何ビットか。(b) 32ビットは何バイトか。(c) 148 バイトのパケット（1-4 で出てくる）は何ビットか。

自分の答えを出してから

使う：P3

1バイト＝8ビットなので、バイト→ビットは ×8、ビット→バイトは ÷8。

(a) 3×8 ＝ 24 ビット　(b) 32÷8 ＝ 4 バイト（IPv4 アドレス1つ分）　(c) 148×8 ＝ 1,184 ビット

問5応用：P3 → C1100 Mbps の回線で、50 MB のファイルを送る。ヘッダなどを考えないとき、最短で何秒かかるか（1 MB ＝ 1,000,000 バイトとする）。

自分の答えを出してから

使う：P3 → C1

単位をビットにそろえます。50 MB ＝ 50×8 ＝ 400 Mb（メガビット）。

b（ビット）と B（バイト）を取りちがえると、答えが 8 倍ずれます（0.5 秒や 32 秒になってしまう）。実際には、ヘッダや確認のやり取りの分だけ、もう少し時間がかかります。

§04

16進数 — 4ビットを1文字で

2進数は 0 と 1 しか使わないので、すぐに桁が長くなります。1バイトでも8桁、MAC アドレス（6バイト）なら48桁です。そこで、ビットの並びを短く書くために16進数を使います。

16進数は 16 種類の文字を使います。0〜9 のあとの 10〜15 は1文字で書けないので、アルファベットの a〜f を使います。

2進数の4桁（4ビット）は 0000〜1111 の 16 通りなので、16進数のちょうど1桁に対応します。だから1バイト（8ビット）を4ビットずつに区切ると、16進数2桁で書けます。

D44ビット＝16進数1桁、1バイト＝16進数2桁導出 ― 自分で導ける

使う：D1・P2・P3

導き方：4ビットは D1 で 2⁴＝16 通り。16進数1桁も 0〜f の 16 通りなので、ちょうど対応する。1バイト（P3）は4ビット2つなので2桁。10進数への変換は、P2 で重みを 16 の何乗かにするだけ。

基数を変えると：8進数なら3ビットずつ（2³＝8）。0-3 のファイルの権限（chmod 644）で使う。

16進数を10進数に直すときも、桁の重みを使います。16進数の重みは、右端が 16⁰＝1、その左が 16¹＝16 です。

16進数の書き方の約束
  • 10進数と区別するために、前に 0x を付けることがある（0xff＝255）。0x 自体は値ではなく「16進数だよ」という印。
  • a〜f は大文字（A〜F）でも同じ意味。5E と 5e は同じ。
  • 1バイトは必ず2桁で書く。10 は a ではなく 0a と書く（MAC アドレスなどで桁がずれないように）。
同じ数の3つの書き方（よく出るもの）

§05

端末で計算して確かめる（Parrot）

ここからは Parrot の端末で、§02〜§04 の計算をコンピューターにやってもらい、答えが合っているか確かめます。この節の演習は計算だけで、通信は行いません。端末を1つ開き、clear で画面を消してから始めます。

手順1：2進数・16進数 → 10進数

COMMAND2進数 1010 を10進数で表示する
echo $((2#1010))
コマンドの分解
部分意味
echo後ろに書いたものを、そのまま画面に表示するコマンド（echo＝こだま）。echo 自身は計算しない。
$(( ))算術展開（arithmetic expansion：計算して、結果に置きかえる）。シェル（コマンドを読み取って実行する係。Parrot の標準は bash（Bourne Again SHell：ボーン・アゲイン・シェル））が、echo を動かす前に中を計算する。決まった書き方。
2#「この後ろの数は 2進数」という指定。進数#数 の形で、2〜64 進数まで書ける。
101010進数に直したい2進数。§02 の例1。ほかの2進数に変えてよい（0 と 1 だけを使う）。

同じ形で、残りの3つも順に打ちます。# の前の数が「何進数か」、後ろが「その進数の数」です。

§06

実物のアドレスをバイトで読む（Parrot）

1章で何度も出てくる MAC アドレス・IPv4 アドレス・ポート番号を、先にバイトとビットの目で読んでおきます。端末は手順2のまま使い、clear してから始めます。

P4アドレスの大きさは規格で決まっている：MAC 48ビット、IPv4 32ビット、ポート番号 16ビット原理 ― 覚える

どんな決まりか：規格。変えるには新しい規格が必要。IPv4 の 32 ビットでは足りなくなり、128 ビットの別の規格 IPv6 が作られた（IPv4 の延長ではないので、そのままでは IPv4 と通信できない。だから今も両方が並んで使われている）。

由来：MAC アドレスは IEEE（Institute of Electrical and Electronics Engineers：米国電気電子学会）の 802 規格で、先頭バイトのビット0・ビット1 の意味もこの規格。IPv4 は RFC 791（1981年）。ポート番号は UDP の RFC 768（1980年）と TCP の RFC 793（1981年。現在は RFC 9293）。

手順3-1：MAC アドレスは6バイト

根拠：D4・P4（先頭バイトのビット1）

本物の NIC の MAC アドレスは、前半3バイトが OUI（Organizationally Unique Identifier：組織固有識別子＝メーカーごとに割り当てられた番号）、後半3バイトがメーカーの中での通し番号で、ビット1 は 0 です。仮想マシンの NIC や、スマートフォンの「プライベートアドレス」機能（Wi-Fi ごとに MAC アドレスを変えて、追跡されにくくする）では、ソフトが番号を作るので、ビット1 が 1 になります。MAC アドレスはソフトで書き換えられるので、MAC アドレスだけで機器を本人確認することはできません。この弱点は 8章（ARP スプーフィング）で関わってきます。

C3IPv4 アドレスは、世界中で約43億個しかない言えること ― 説明できる

根拠：D1・P4

IPv4 は 32 ビットなので、D1 から 2³²＝4,294,967,296 通り。世界中の機器には足りないので、家庭や会社の中ではプライベートアドレスを使い、出口で NAT（Network Address Translation：ネットワークアドレス変換）が書き換える（1-1 で出てくる）。根本の解決として作られたのが、128 ビットの別の規格 IPv6。

応用問題（§06・全4問）

問9応用：P4 → D4 → C2Kali の内部ネットワーク側の MAC アドレスは 12:ae:d8:64:04:33 である（1-4 §04 で出てくる）。
(a) 先頭バイト 12 を8桁の2進数にし、ビット0・ビット1 がそれぞれ何を表すか答えよ。
(b) ARP（Address Resolution Protocol：アドレス解決プロトコル）の「だれ？」の問い合わせは、宛先 MAC アドレス ff:ff:ff:ff:ff:ff で送られる（1-1 §04 で出てくる）。先頭バイトのビット0 は何か。それは何を意味するか。

自分の答えを出してから

使う：P4（ビット0・ビット1 の意味）・D4

(a) 0x12 ＝ 1×16＋2 ＝ 18 ＝ 16＋2 ＝ 2⁴＋2¹ → 00010010。
ビット0（右端）＝ 0：1台宛て（ユニキャスト）。ビット1（右から2つ目）＝ 1：ローカルで決めた番号。Parrot と同じく、仮想化ソフトが作った番号です。

(b) ff ＝ 11111111 なので、ビット0 は 1＝グループ宛て。ff:ff:ff:ff:ff:ff（48ビットすべて 1）は、グループ宛ての中でも「同じネットワークの全員宛て」を表す特別な番号（ブロードキャストアドレス）です。だから ARP の「だれ？」は全員に届きます。

問10応用：D5Parrot の NAT 側（インターネット側）の出口は Mac の 192.168.64.1 である（1-3 で出てくる）。このアドレスを16進数8桁で書け。また、何バイトか答えよ。

自分の答えを出してから

使う：D3・D4

4つの数を、それぞれ16進数2桁にします。

192 ＝ 12×16＋0 → c0、168 ＝ 10×16＋8 → a8、64 ＝ 4×16＋0 → 40、1 → 01

答え：c0a84001（16進数8桁＝4バイト）。

先頭の c0a8（192.168）は、§06 の 192.168.128.3 と同じです。3番目の数（64 と 128）だけがちがうことが、16進数でも 40 と 80 のちがいとして見えます。

問11応用：P4 → D1 → C4・C5(a) ポート番号 70000 が使えないのはなぜか、ビットの数を使って説明せよ。(b) 70000 を表すには最低何ビット必要か。

自分の答えを出してから

使う：P4・D1

(a) ポート番号は 2バイト＝16ビットの入れ物で、入る数は 0〜65,535（2¹⁶−1）まで。70,000 はそれより大きいので、入れ物に入りきらないから使えません。

(b) 2¹⁶ ＝ 65,536 では足りず、2¹⁷ ＝ 131,072 なら足りるので、17 ビット。

「決まった大きさの入れ物に、入りきらない数やデータを入れようとする」とどうなるかは、セキュリティでとても大事なテーマです。12章のバッファオーバーフローで、メモリの入れ物について同じ問題を扱います。

問12応用：P4 → D5（初めて見る規格）IPv6 アドレスは 128 ビットである。(a) 何バイトか。(b) 16進数で何桁か。(c) IPv6 アドレスは、全部で 2 の何乗通りあるか。IPv4 の何倍か、2 の何乗で答えよ。

自分の答えを出してから

使う：P3・P4・D1・D4

この節では IPv6 を扱っていませんが、原理と導出がわかっていれば解けます。

(a) 1バイト＝8ビット（P3）なので、128÷8 ＝ 16 バイト。

(b) 1バイト＝16進数2桁（D4）なので、16×2 ＝ 32 桁（4ビット＝1桁と考えても 128÷4＝32）。

(c) D1 から 2¹²⁸ 通り。IPv4 は 2³² 通りなので、2¹²⁸÷2³² ＝ 2⁹⁶ 倍（同じ数を掛けた回数の引き算：128−32＝96）。

実際の IPv6 アドレスは、16進数32桁を4桁ずつ : で区切って書きます（例：2001:0db8:0000:0000:0000:0000:0000:0001。この 2001:db8:: で始まる範囲は、説明用に決められた番号）。1-3 で出てくる fe80:: で始まるアドレスも IPv6 アドレスです。

§07

バイトと16進数が出てくる場面

この先の講座では、バイトと16進数が何度も出てきます。どれも「何バイトか」「16進数で何桁か」が読めれば、表示の意味がつかめます。

  • パケットの大きさと中身：1-4 では、148 バイトのパケットが Ethernet 14＋IP 20＋TCP 32＋HTTP 82 バイトに分かれていることを確かめます。次の 0-2 では、ファイルやパケットの中身を16進数2桁ずつ並べて表示する方法（16進ダンプ）を学びます。
  • ハッシュ値：ファイルの「指紋」にあたる値。SHA-256 は 256 ビット＝32 バイトで、16進数 64 桁で表示されます。14章のマルウェア解析で、ファイルが既知のマルウェアかを調べるのに使います。
  • メモリの番地：プログラムがメモリのどこを使っているかは、0x7ffd… のような16進数で表されます（0-4、12章）。
  • 大きさの限界：「1バイトには 255 までしか入らない」「決まった大きさの入れ物に、それより大きいデータを書くと何が起きるか」という感覚は、12章のバッファオーバーフローの土台になります。
C5決まった大きさに入りきらない数やデータは、セキュリティの弱点になりうる言えること ― 説明できる

根拠：D3・D5

入れ物の大きさを確かめずに書きこむと、となりの領域をこわす。12章のバッファオーバーフローは、この問題がメモリで起きたもの（問11）。
