1-4　階層モデル（OSI / TCP-IP）で全体を捉えるばらばらに見えたプロトコルを、1枚の絵にまとめる

1-1〜1-3 で、Ethernet・IP・ICMP・TCP・UDP・DNS・HTTP と、たくさんのプロトコル（通信の約束ごと）が出てきました。これらはばらばらに動いているのではなく、役割ごとに重なって（層になって）動いています。この重なり方を整理したものが階層モデルです。

この節では、TCP/IP モデルと OSI 参照モデルという2つの階層モデルを学び、Kali から Parrot の Web サーバーに接続したときのパケットを1つ取り出して、層ごとに分解して見ます。層の目で見られるようになると、「この攻撃はどの層の仕組みを悪用しているか」「この守りはどの層で効くか」を整理できるようになります。1章のまとめの節です。

読み方：コマンドは、右端のコピーボタン（重なった四角のアイコン）でコピーできます。各コマンドの下に、全パーツの意味と出力の読み方を載せています。

§01

階層モデル — 通信を役割で分ける

この節で押さえること
  • 通信は、役割ごとの層に分けて作られている。TCP/IP モデルでは4つの層。
  • 層ごとに使う住所・番号がちがう：MAC アドレス → IP アドレス → ポート番号 → 中身。
  • 層に分けると、1つの層を取り替えても、ほかの層はそのまま使える。

荷物を海外に送る場面を考えてみます。手紙を書く人は、中身のことだけを考えます。宛名を書く人は住所だけ、運送会社はトラックか飛行機かだけを考えます。それぞれが自分の役割だけを受け持ち、ほかの役割の中身は気にしない——こうしておくと、運び方がトラックから飛行機に変わっても、手紙の書き方は変えなくて済みます。

ネットワークも同じ考え方で作られています。たとえば、有線の LAN（Local Area Network：構内ネットワーク）でも Wi-Fi でも、Web ページの見方（HTTP：HyperText Transfer Protocol＝ハイパーテキスト転送プロトコル）は同じです。下の層（線か電波か）が変わっても、上の層はそのまま使えるからです。

この講座でこれまでに見たプロトコルを、層に当てはめると次のようになります。

層（TCP/IP モデル）プロトコル出てきた節
アプリケーション層HTTP、DNS（Domain Name System：ドメインネームシステム）1-2、1-3
トランスポート層TCP（Transmission Control Protocol：伝送制御プロトコル）、UDP（User Datagram Protocol：ユーザー・データグラム・プロトコル）1-2、1-3
インターネット層IP（Internet Protocol：インターネット・プロトコル）、ICMP（Internet Control Message Protocol：インターネット制御メッセージプロトコル）1-1、1-3
ネットワークインターフェース層Ethernet（イーサネット：有線 LAN の規格）、ARP（Address Resolution Protocol：アドレス解決プロトコル）1-1
ICMP と ARP は「どっちの層？」

ICMP は IP パケットの中に入って運ばれますが、TCP や UDP の仲間ではなく、IP の付属品としてインターネット層に置かれます（1-3 §02）。ポート番号を持たないのも、そのためです。

ARP は「IP アドレス（インターネット層の住所）から MAC アドレス（インターフェース層の住所）を調べる」役目なので、2つの層のつなぎ役です。TCP/IP モデルでは、ネットワークインターフェース層の側に置くことが多いです（§06）。

§02

TCP/IP モデルと OSI 参照モデル

階層モデルには、よく使われるものが2つあります。

  • TCP/IP モデル（4層）：実際のインターネットの作りに合わせたモデル。この講座で見てきたプロトコルは、このモデルに沿って作られています。
  • OSI 参照モデル（7層）：OSI（Open Systems Interconnection：開放型システム間相互接続）は、ISO（International Organization for Standardization：国際標準化機構）が決めた、通信を7つの層に分けて考えるための考え方の枠組みです（ISO は英語の頭文字なら「IOS」になりそうですが、頭文字ではありません。ギリシャ語の isos（等しい）から取った名前で、どの言語でも同じ「ISO」になるように決められています）。実際のインターネットは OSI のとおりには作られていませんが、「どの層の話か」を言うときの共通の番号として広く使われています。

セキュリティの話では、OSI の番号で「L2（レイヤー2：Layer 2＝第2層）の攻撃」「L7 のファイアウォール」のように呼ぶことがよくあります。L2 はデータリンク層（MAC アドレスの層）、L3 はネットワーク層（IP の層）、L4 はトランスポート層（ポートの層）、L7 はアプリケーション層です。

層ごとの「荷物の呼び方」

同じデータでも、どの層の目で見ているかによって呼び方が変わります。この呼び方をまとめて PDU（Protocol Data Unit：プロトコル・データ・ユニット＝その層が扱う1つ分のかたまり）と言います。

層呼び方例
アプリケーション層データ、メッセージHTTP の依頼「GET /」
トランスポート層セグメント（TCP）、データグラム（UDP）TCP のヘッダが付いたもの
インターネット層パケットIP のヘッダが付いたもの（1-1 で「パケット」と呼んできたもの）
ネットワークインターフェース層フレーム（frame）Ethernet のヘッダが付いたもの。実際に線を流れるのはこれ（前後に、記録には残らない合図なども付く：§05）

日常会話では、どの層でもまとめて「パケット」と呼ぶことが多く、この講座でもそうしてきました。§05 の tshark は、Ethernet まで含めた1つ分を「Frame」と表示します。

§03

カプセル化 — 包んで、はがす

送る側では、上の層から順に、それぞれの層が自分のヘッダ（送り状）を付けて包みます。これをカプセル化（encapsulation：カプセルに包むこと）と言います。受け取る側では、逆に下の層から順にヘッダを読んではがし、中身を上の層に渡します。1-1 §01 の「封筒の中に封筒」の正体が、これです。

それぞれの層は、相手のマシンの同じ層とだけ話しているように振る舞います。Kali の TCP は Parrot の TCP と通し番号（1-2）をやり取りし、Kali の HTTP は Parrot の HTTP と「ください」「どうぞ」をやり取りします。そのとき、下の層がどうやって運んでいるかは気にしません。

層ごとに「住所」がちがう

層ごとに、使う住所・番号がちがいます。とくに大事なのが、MAC アドレスと IP アドレスの役割のちがいです。

  • MAC アドレス（インターフェース層）：同じネットワークの中で、すぐ隣の機器に渡すための住所。ルーターを越えるたびに付け替わる。
  • IP アドレス（インターネット層）：最後の宛先のマシンの住所。途中で原則として変わらない（NAT では送信元が書き換わる。外から内側の機器へ通すポート転送のように、宛先が書き換わる仕組みもある）。
  • ポート番号（トランスポート層）：そのマシンの中のどのプログラム宛てか。
§04

層ごとの住所：MAC アドレス（Kali・Parrot）

IP アドレスは 1-1 §03 で確かめました。ここでは、そのひとつ下の層の住所、MAC アドレス（MAC：Media Access Control＝媒体アクセス制御）を見ます。MAC アドレスは、NIC（Network Interface Card：ネットワーク・インターフェース・カード。1-1 §02）1枚ごとに付いている番号です。演習を始める前に、Kali と Parrot の端末をすべて clear しておきます。

§05

Kali から Parrot の Web サーバーに接続して、そのときのパケットをファイルに記録し、あとから層ごとに分解して読みます。1-2 と同じく、Parrot で Web サーバーを動かしておきます。

準備Parrot の端末B で Web サーバーを起動する（動かしたままにする）
python3 -m http.server 8080 --directory ~/www

sudo tcpdump -i eth1 -n -c 10 -w /tmp/l4.pcap 'tcp port 8080'

もう一度記録すると Permission denied になるとき

同じコマンドで2回目の記録をすると、tcpdump: /tmp/l4.pcap: Permission denied（許可がない）と出て、記録できないことがあります。Kali の tcpdump は、安全のために、作ったファイルの持ち主を tcpdump という専用の利用者に変えます。/tmp は、だれでもファイルを置ける共有の場所なので、Linux は「ほかの利用者のファイルを上書きさせない」保護をかけていて、管理者として開き直そうとしても断られるのです。もう一度記録するときは、先に古いファイルを消します。

sudo rm /tmp/l4.pcap

rm は remove（取り除く）の略で、ファイルを消すコマンドです。持ち主を確かめたいときは、消す前に次のコマンドを実行すると、持ち主の欄に tcpdump と表示されます（Kali の初期設定の場合）。

ls -l /tmp/l4.pcap

ls は list（一覧）の略でファイルの一覧を出すコマンド、-l は long（長い形式）の頭文字で、持ち主や大きさまで表示する指定です。

§06

IP と MAC の対応表を見る（Kali）

§05 で、Kali は Parrot の IP アドレスしか指定していないのに、Ethernet の宛先には Parrot の MAC アドレスが正しく書かれていました。Kali はどうやって Parrot の MAC アドレスを知ったのでしょうか。その答えが、OS が持っている「近所の名簿」です。

この名簿が書き換えられたら？

Kali は、この名簿を信じて Ethernet の宛先を決めています。もし、だれかがうその ARP の返事を送って「192.168.128.3 の MAC アドレスは、わたしの番号です」と名簿を書き換えさせたら、Kali が Parrot に送ったつもりのフレームは、その人のところに届いてしまいます。これが 8章で原理と見つけ方・守り方を学ぶ ARP スプーフィング（spoofing：なりすまし）で、インターフェース層（L2）の仕組みを悪用した攻撃です。ip neigh で名簿を確かめることは、その見つけ方の第一歩になります。

§07

層ごとの攻撃と守り

層の目で見ると、これから学ぶ攻撃と守りを「どの層の話か」で整理できます。攻撃は「どの層の仕組みを悪用しているか」、守りは「どの層で見張り・止めるか」です。

守りの道具は、見える層が決まっている

守りの道具は、それぞれ見える層が決まっています。たとえば、ふつうのファイアウォール（5章・18章の nftables）は、IP アドレスとポート番号で「通す・止める」を決めます。そのため、80番（HTTP）を通すと決めたら、その中身が普通の依頼なのか、攻撃なのかは見ていません。HTTP の中身まで見て判断するのが WAF（Web Application Firewall：Web アプリケーション・ファイアウォール。11章）です。

この節の核心：1つの層だけでは守れない

攻撃は、どの層からでも来ます。L2 の名簿の書き換えは、L3・L4 のファイアウォールでは止められず、L7 の中身の攻撃は、ポートで止めるファイアウォールを素通りします。だから守りは、層ごとに別の道具を重ねるのが基本です（多層防御：18章）。また、§05 の User-Agent や 1-1 の送信元 IP のように、上の層にも下の層にも「自己申告」の情報があることを忘れないようにしましょう。

§08

まとめとチェック

  • 通信は層に分けて作られている。TCP/IP モデルは、アプリケーション層・トランスポート層・インターネット層・ネットワークインターフェース層の4つ。OSI 参照モデルは7つで、セキュリティでは「L2」「L7」のように OSI の番号で呼ぶことが多い。
  • 送る側は上の層から順にヘッダを付けて包み（カプセル化）、受ける側は下から順にはがす。同じ層どうしがやり取りしているように振る舞う。
  • 層ごとに住所がちがう。MAC アドレスはすぐ隣まで（区間ごとに付け替わる）、IP アドレスは最後の宛先まで、ポート番号はマシンの中のどのプログラムか。
  • 1つのパケット（#4・148バイト）は、Ethernet 14＋IP 20＋TCP 32＋HTTP 82 でできていた。tshark の -O で層ごとに見られる。
  • IP アドレスから MAC アドレスを引く名簿は ip neigh で見られる。この名簿を書き換える攻撃が ARP スプーフィング（8章）。
  • 守りの道具は見える層が決まっているので、層ごとに守りを重ねる。
